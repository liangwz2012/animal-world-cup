# 技术架构

## 目标

把比赛规则与手感同 3D 引擎和微信平台解耦，使双引擎能公平对比，正式引擎也可在不重写玩法的前提下升级。

数据流：触控/AI/回放输入 → 30Hz 纯 TypeScript MatchCore → 快照与事件 → PresentationPort → LayaAir 或 Galacean；WeChatPort 单独处理生命周期、资源、存储和输入。

## 边界

### packages/match-core

- 固定 30Hz、可注入随机种子、无 DOM/WebGL/引擎导入。
- 负责移动意图、足球状态、占有权、传球、射门、抢断、边界、进球和最小比赛状态机。
- 相同输入回放必须得到相同校验值。

### packages/presentation-3d

- 定义角色、足球、镜头、动画、脚接触、特效和音频的引擎无关合同。
- 双引擎消费同一数据，不得各自复制规则或调不同手感参数。

### packages/platform-wechat

- 封装安全区、前后台、音频解锁、分包、缓存、存储、网络和错误恢复。
- 核心业务不直接散落 wx.* 调用。

### experiments

- 只放候选引擎薄适配层与同题场景。
- 使用同一相机、灯光目标、压缩资产、UI、测量脚本和设备矩阵。

## M0 同题切片

- 64m × 42m 球场，1 名可控球员、1 名队友、1 名防守者、1 个独立足球。
- 待机、慢跑、冲刺、传球、射门、失衡六类动作，共享 Humanoid 骨架和脚接触元数据。
- 支持移动、短传、蓄力射门、追球、简单防守、进球复位。
- 阴影、动画混合、相机跟随、触球特效、基础观众实例和分包模拟资源。
