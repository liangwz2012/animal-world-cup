# Goal：M0 3D 引擎决策门

状态：进行中
建立日期：2026-08-02
项目：乡村足球赛3D

## 目标

用同一份固定 30Hz TypeScript 足球模拟、同一套角色/动画/场地资产和同一套微信测试合同，分别完成 LayaAir 3.x 与 Galacean 1.x 的最小 3D 足球纵向切片，取得可复现的 Web、微信开发者工具、Android/iOS 真机、包体、性能、恢复和开发效率证据，并通过 ADR-0001 选出唯一正式引擎。

## 范围

- 复核并锁定候选引擎、Node、包管理器、微信开发者工具和资产工具版本。
- 建立纯 TypeScript MatchCore：固定步长、种子随机、最小球员/足球/传射/抢断/进球和回放校验。
- 建立引擎无关表现合同与微信平台端口。
- 准备测试场、共享 Humanoid 角色、足球、六类动作、脚接触元数据和基础 3D 表现。
- 在 LayaAir 与 Galacean 实现等价切片，不复制玩法逻辑。
- 自动输出包体、构建时间、回放、循环、故障恢复和 Web 性能结果。
- 执行微信开发者工具及 Android/iOS 真机合同。
- 写 ADR-0001 并更新 docs/STATUS.md。

## 非范围

- 正式 5v5、完整 AI、犯规/越位、联网对战。
- 全国行政数据、在线排行、赛季服务、支付、广告和提审。
- 贵州正式美术、全国人物/球衣量产、面部系统、完整观众和解说。
- 购买付费资产/云服务或使用许可证不明素材。
- 在证据完成前选引擎，或长期维护两套正式客户端。

## 完成条件

1. 两个候选均有可复现源码构建、Web 演示和微信候选包；硬失败者保留最小复现与证据。
2. 两者消费同一 MatchCore、资产、回放和配置，模拟校验值一致。
3. docs/ACCEPTANCE.md 每项有真实结果。
4. 至少一台 Android 和一台 iOS 完成同版本真机记录；缺少则 Goal 保持未完成。
5. ADR-0001 选出唯一引擎并说明淘汰原因、迁移代价、风险和回退条件。
6. docs/STATUS.md 如实更新，自动检查通过，M0 形成独立提交。

## 验证方式

- 结构、类型、单测、确定性回放和双适配合同自动检查。
- 从干净依赖构建 Web/微信包，记录版本、耗时和逐文件体积。
- 同设备运行 10 分钟、20 次场景循环、20 次前后台切换，并注入资源超时/损坏。
- 记录平均帧率、P95 帧时间、峰值内存、首局时间和输入延迟。
- 人工检查轮廓、动画混合、脚滑、触球、球速、镜头、降档与恢复。
- 原始证据放 tests/evidence/raw，受控摘要记录设备、版本、时间和结论。

## 外部阻塞

- 到达真实验收步骤时，如需微信扫码、AppID 或真机连接，只请求用户完成一次必要动作。
- 不用虚构设备数据替代真机。
- 同类外部错误最多重试两次，随后保留复现并改走可验证替代路径。

## 停止条件

全部完成后更新状态并停止，不进入 M1-A。若两候选都硬失败，先写失败 ADR；只有这时才允许建立 Cocos Creator 3.8.x 保底实验，且仍属于 M0。

## 模型建议

当前 M0 推荐 gpt-5.6-sol + Medium：它包含架构决策、双引擎公平实验、微信兼容、3D 动画/资源管线和最终裁决。反复平台疑难或 ADR 终审才临时提高到 High；不要仅因运行时间长使用 XHigh、Max 或 Ultra。

后续边界清晰的功能里程碑可在新 Goal 中选 gpt-5.6-terra + Medium 完成功能、测试和普通修复，再由 Sol 做关键设计或终审。运行中的主任务不会只靠文字自动换模，应在新里程碑中真实选择。
