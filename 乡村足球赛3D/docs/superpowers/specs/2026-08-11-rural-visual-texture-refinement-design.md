# M0 乡村视觉贴图精修设计

日期：2026-08-11

状态：已获用户批准并完成规格自审，待用户书面复核

项目：《乡村足球赛3D》

## 1. 目标

在不改变 M0 双引擎公平评测、MatchCore、共享骨架、六段动作和独立足球合同的前提下，为 LayaAir 与 Galacean 共用的最小比赛切片建立一套可辨认、可复现、可降级的“中国乡村动画电影感”材质语言。

本次采用已批准的 A 方向“黔岭暖阳”：以贵州西南山地气质为灵感，使用暖阳、冷天光、灰瓦木屋、夯土与石灰岩、节庆红和靛蓝棉布，形成圆润柔软但保留真实乡土痕迹的画面。工作重点按场景 70%、人物 30% 分配。

这是一套 M0 共用视觉精修小样，不是 M1-B 贵州正式主场美术，不得写成正式地图、正式角色或“皮克斯级成品”。

## 2. 当前问题

当前 M0 金样已能验证 GLB、皮肤动画、独立足球、同回放和双引擎加载，但画面主要依赖纯色材质与规则方块：

- 球场外是单色背景，没有山势、村落轮廓或空气层次。
- 草地、木看台、横幅、人物服装均缺少材质尺度、粗糙度和边缘变化。
- 场景没有稳定的地域识别点，容易落入通用低成本低模球场。
- 人物轮廓可读，但肤色、棉布、短裤与球鞋只靠单色区分。
- 双方向光满足技术验证，但尚未形成暖侧光、冷天光、接触阴影和轻空气透视的电影层次。

## 3. 范围

### 3.1 本次包含

- 生成并保留 8 张项目源贴图：梯田草坪、夯土边坡、灰陶瓦、暖夯土墙、旧杉木、喀斯特石、节庆红布、靛蓝棉布。
- 将源图规范化为可平铺、无文字、无徽标、无烘焙方向光的基础色贴图。
- 为 M0 环境补充轻量山地远景层、村屋轮廓、石阶或夯土边坡，使地域气质进入比赛主镜头。
- 将场景贴图接入共享环境 GLB；将棉布、肤色与球鞋材质调整接入共享人物 GLB。
- 以确定性程序生成粗糙度参数与最多两张共享微法线图；AI 生成图只作为基础色源，不直接冒充物理准确的 PBR 数据。
- 两个引擎继续消费相同 GLB、贴图、回放、镜头意图与画质降级规则。
- 增加贴图规格、大小、GLB 引用、资源一致性、回退路径和视觉截图验收。
- 登记生成方式、日期、用途、提示词、后处理与输出文件，更新资产来源记录。

### 3.2 本次不包含

- 正式贵州主场、完整村落、5v5 阵容、观众、餐饮摊位、民族节庆量产或全国地区资产。
- 复杂面部、头发卡片、布料模拟、逐角色独立贴图、动作捕捉、IK 或新骨架。
- 真实赛事名称、真实队徽、赞助商、真实人物肖像、未经审核的民族纹样或可识别商标。
- 修改 MatchCore 数值、比赛玩法、回放结果或当前引擎决策标准。
- 微信开发者工具或真机结论；本地 Web 通过不能写成微信真机通过。

## 4. 视觉系统

### 4.1 造型与质感

- 造型：大轮廓圆润，建筑与看台边缘避免锋利积木感；远景采用大形体，不堆微小装饰。
- 材质：中高粗糙度、柔和高光、可见但克制的纤维、木纹、土层和石灰岩矿脉。
- 真实感：保留修补、踩踏、雨蚀和轻微色差，但禁止脏污覆盖主体颜色。
- 可读性：足球、球衣、边线和球门保持最高对比；环境纹理不得制造类似边线或足球的高对比噪点。
- 地域性：依赖山势、灰瓦、夯土、石灰岩和靛蓝/节庆红配色，不依赖未经审核的符号拼贴。

### 4.2 色彩与光照

- 天空与远景：青蓝天光、低饱和蓝绿色山体、轻暖雾。
- 场地：草地使用黄绿到深绿的低频变化，磨损区偏暖，不做荧光绿。
- 建筑：灰陶瓦、暖赭土墙、深褐杉木和灰白石灰岩。
- 强调色：节庆红用于横幅与少量视觉锚点；靛蓝用于短裤或局部服装。
- 光照：暖侧逆光为主、冷天光为辅；阴影柔和并稳定；远景通过轻雾降低对比。

| T02 | 夯土边坡 | 场边土坡/路径 | 细砂、浅裂、雨蚀 | 深坑、强阴影、车辙焦点 |

| T06 | 喀斯特石 | 石阶与挡墙 | 灰白石灰岩、浅矿脉 | 大裂缝、化石焦点、湿亮表面 |

生成源图采用内置图像生成工具，每个资产独立调用。提示词统一包含：`stylized-concept`、游戏可平铺基础色贴图、正交俯视、均匀无方向光、无阴影、无 AO、无高光、无文字、无徽标、无水印、边缘连续。单项若有明显接缝、文字、徽标或光照烘焙，只允许针对该问题重生成一次；第二次仍失败则改用程序化材质回退。

源图保存为项目资产并保留原始分辨率；运行时版本统一导出为 512×512、sRGB 基础色。仅 T07 在确有透明布边需求时保留 Alpha；首轮默认所有贴图均为不透明，避免引入排序和压缩复杂度。

## 6. 资产与代码架构

### 6.1 文件边界

- `assets/source/m0/textures/generated/`：8 张原始生成图与来源记录。
- `assets/source/m0/textures/runtime/`：规范化后的 512×512 运行时基础色图。
- `assets/source/m0/textures/manifest.json`：ID、用途、提示词摘要、尺寸、色彩空间、哈希、运行时文件与回退色。
- `tools/process-m0-textures.mjs`：尺寸、色彩、压缩、接缝预览和清单校验。
- `tools/blender/build_m0_gold.py`：共享 UV、材质节点、微法线/粗糙度和环境远景几何。
- `assets/built/m0/`：重新生成的共享 GLB 与预览截图，继续按现有规则视为构建产物。

如果现有构建工具不支持所需图像处理，优先使用项目已存在或工作区提供的 Pillow；不得为八张贴图引入大型运行时依赖。

### 6.2 数据流

1. 内置图像生成工具按 T01–T08 独立生成项目源图。
2. 本地处理脚本读取清单，统一尺寸、色彩模式和文件名，生成 2×2 平铺检查图并计算哈希。
3. Blender 构建器读取运行时贴图，为共享环境与人物材质配置 UV、颜色、粗糙度和微法线。
4. 构建器导出 `m0-environment.glb`、`m0-player.glb`、`m0-ball.glb`；球模型和足球实体合同不变。
5. LayaAir 与 Galacean 继续从相同资源 URL 加载三份 GLB，不在引擎适配层复制材质逻辑。
6. 资源加载失败或低画质模式下，切回当前纯色材质或不带微法线的基础色版本，比赛必须继续启动。

### 6.3 引擎侧边界

- 引擎适配层只负责等价灯光、阴影、雾和画质开关，不拥有地域材质数据。
- 相机位置、视场角和回放保持一致，避免用不同镜头掩盖渲染差异。
- 若某引擎不支持同等微法线或雾实现，保留最小复现并在证据中标注；不得静默删除另一引擎的同类内容。

## 7. 性能与降级

- 运行时贴图集（8 张基础色与最多 2 张共享微法线图）合计目标不超过 1.1 MiB；共享环境、人物和足球组件合计仍以 M0 现有体积门禁为基线，若必须调整门禁需记录增量与理由，不能直接放宽。
- 首选 512×512 基础色图；仅当同镜头人工检查证实明显不足时，单张升到 1024×1024，并保持总预算。
- 高档：基础色 + 微法线/粗糙度 + 远景层 + 柔和阴影。
- 中档：基础色 + 简化粗糙度 + 远景层，减弱或关闭微法线。
- 低档：基础色或当前纯色材质，关闭微法线、雾与额外阴影采样。
- 任何降级均不得影响 MatchCore、足球位置、碰撞、动画语义或回放校验值。

## 8. 错误与回退

- 生成失败：单项重试一次；仍失败则使用程序化纹理和明确的来源记录。
- 处理失败：保留源图，停止该资产进入 GLB；不得用尺寸或色彩模式不合规的文件凑数。
- GLB 构建失败：保留当前 M0 纯色构建作为可运行回退，输出错误资产 ID。
- 运行时贴图加载失败：使用材质清单中的回退色，不阻塞候选场景启动，并写入诊断。
- 双引擎表现不等价：保留同镜头截图和最小复现，在修复前不得用该项给任一候选加分。
- 超过体积预算：先降低纹理尺寸或压缩质量，再减少微法线；不得删除地域核心资产来掩盖预算问题。

## 9. 验证与完成条件

### 9.1 自动验证

- 8 个资产 ID 完整且文件存在；源图、运行时图和清单哈希一致。
- 运行时图全部为 512×512、RGB/RGBA、可被 Blender 和两个引擎加载。
- 平铺预览没有明显边界；自动检测只作为提示，最终接缝由人工复核。
- GLB 仍满足 glTF 2.0、一个 skin、17–65 根变形骨、六段动作名、独立足球和可解析结构。
- LayaAir 与 Galacean 构建消费同一组资产 URL，回放最终校验值保持 `322232d0`。
- 现有类型检查、单元测试、资产合同、Web 候选构建与微信候选构建不回退。
- 构建报告记录贴图及 GLB 的逐文件大小与相对当前基线的增量。

### 9.2 人工视觉验收

- 同一 1280×720 比赛镜头下，可在三秒内辨认山地乡村、灰瓦/夯土和节庆红视觉锚点。
- 草地纹理尺度自然，不出现巨型草叶、明显平铺格或与边线竞争的高对比纹理。
- 球员红衣、靛蓝短裤、肤色、白袜、黑鞋在远镜头仍能分区。
- 近景材质有柔和织物、木纹和土石层次，但不出现写实脏污或塑料高光。
- 足球、边线、球门和球员轮廓的可读性不低于当前 M0 截图。
- 两引擎同镜头差异被记录；只有获得微信开发者工具和真机证据后，才可陈述平台验收结果。

### 9.3 停止条件

当 8 张源图与运行时图、共享 GLB、双引擎 Web 截图、自动测试、资产来源记录和 `docs/STATUS.md` 更新全部完成后，本精修工作包停止。不得自动扩展到正式贵州地图、更多角色、观众或下一里程碑。

## 10. 设计取舍

选择“黔岭暖阳”而不选择高饱和糖果风，是为了同时满足亲和力、地域可信度和手机比赛可读性；不选择低饱和乡土绘本风，是因为远镜头角色和足球识别风险更高。

采用少量共享贴图 + 程序化 PBR 辅助，而不是每个物件独立生成整套 PBR，是为了控制微信包体、保持两引擎一致并让资产可以重新构建。将本次明确限定为 M0 视觉精修小样，是为了不绕过当前引擎决策门，也避免把概念探索误报为正式贵州美术完成。
