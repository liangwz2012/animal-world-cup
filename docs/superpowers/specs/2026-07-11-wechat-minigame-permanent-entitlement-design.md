# 微信小游戏永久畅玩权益与兑换码预留设计

## 决策

当前无版号上线版本不销售虚拟道具，不销售“无限玩兑换码”，不显示兑换码输入框、价格、购买联系方式、付款二维码或任何引导玩家私下购买的文案。

客户端只预留通用的“永久畅玩权益”读取接口，默认值固定为关闭。该权益不能通过远程运营配置开启，也不能通过本地调试字段或普通缓存伪造。取得版号、完成平台支付接入并再次评估提审要求后，才实施面向玩家的购买和兑换流程。

## 当前版本行为

- 玩家仍按“初始免费局数＋看广告/转发二选一增加局数”游玩。
- 当前发布包不包含可见兑换码页面或按钮。
- 远程配置不提供 `redeemCodeEnabled`、价格、购买链接或联系方式字段。
- 不从网页、客服、二维码或个人收款渠道出售游戏内权益。
- 内部测试不能在正式环境给普通玩家形成可购买的永久权益。

## 预留接口

局数门槛只依赖一个只读权益判断：

```text
EntitlementProvider.has("unlimited_play") -> boolean
```

当前实现使用 `DisabledEntitlementProvider`，始终返回 `false`。`QuotaGate` 的顺序为：

1. 如果存在经过服务端验证的 `unlimited_play` 权益，则允许开始且不消耗局数。
2. 否则消费现有可玩局数。
3. 局数不足时显示广告/转发二选一解锁面板。

当前版本没有能够生成永久权益的公开入口。接口存在的目的只是避免未来获得版号后重写局数门槛，不代表当前已经开放付费能力。

## 未来取得版号后的正式方案

后续单独立项并提审，采用微信官方虚拟支付或当时平台认可的支付能力：

- 客户端发起官方订单，不直接相信前端支付结果。
- 平台服务端通知开发者服务器发货。
- 服务器按订单号幂等发放 `unlimited_play` 权益。
- 客户端登录后从服务器读取签名权益状态。
- 如果保留兑换码，兑换码只作为官方活动或合规订单的发放凭证，不承担私下收款功能。
- 兑换码必须服务端一次性核销，包含有效期、状态、权益类型和审计记录；客户端不得离线验证或内置万能码。
- iOS、安卓、PC 和鸿蒙按当时平台支付支持情况分别处理，不以外部支付绕过不支持的平台。

## 安全边界

- 永久权益不能仅存于 `wx.setStorageSync`，否则清缓存、改包或伪造本地值会破坏计费状态。
- 远程配置只能控制已合规开放的运营数值，不能把 `DisabledEntitlementProvider` 切换为付费实现。
- 不在客户端保存兑换码全集、生成算法、支付密钥、AppSecret 或服务端签名密钥。
- 正式权益响应需要绑定玩家 OpenID/业务用户 ID、环境、权益版本和服务端签名。
- 开发版、体验版和正式版使用不同环境，测试权益不得进入正式账号。

## 审核门

只有同时满足以下条件才允许开始开发并开启面向玩家的付费入口：

1. 游戏取得有效版号及相关出版运营资质。
2. 微信公众平台为该 AppID 开通相应虚拟支付能力。
3. 支付、发货、退款、未成年人限制和客服流程已经完成。
4. 当前平台对 iOS、安卓、PC 和鸿蒙的支付规则已经重新核验。
5. 产品负责人明确批准新的提审版本；不得仅通过远程配置在旧版本中开启。

## 测试要求

- 当前正式构建中 `has("unlimited_play")` 必须始终为 `false`。
- 远程配置即使返回兑换码或永久权益字段也必须被白名单过滤。
- 普通玩家无法通过本地存储获得永久权益。
- 当前 UI 中不存在购买、兑换、联系作者或付款入口。
- 局数门槛在禁用权益提供器下继续正确执行免费局数和广告/分享奖励。
- 未来更换正式服务端权益提供器时，需新增支付通知幂等、兑换码一次性核销、账号绑定、退款撤销和跨端一致性测试。
