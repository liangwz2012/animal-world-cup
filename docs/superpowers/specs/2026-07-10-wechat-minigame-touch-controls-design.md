# 微信小游戏原网站触控层移植规格

日期：2026-07-10  
目标工程：`wechat-minigame-original-runtime-latest`  
状态：已实现并通过微信开发者工具可见控件验证；真机触摸待验证

## 1. 目标与边界

把原网站 `app/match/TouchControls.jsx` 与 `app/match/match.css` 中已经使用的手机触控方案移植到微信小游戏，使当前“能播放”的原版比赛变成“可见、可理解、可操控”的比赛。

本次只处理单机一名玩家的比赛控制层，不修改原版 AI、物理、比赛规则、镜头数值、球员资源或贴图质量；包体拆分作为后续独立任务处理，避免输入与资源变更互相干扰。

## 2. 既有交互是唯一设计来源

控制布局沿用原网站，不重新设计：

- 左下角为模拟摇杆，带固定底盘和随手指移动的摇杆帽；
- 右下角为菱形动作区：上方挑传、左侧传球、右侧铲球、下方射门；
- 菱形中央为长按冲刺；
- 不显示切人键，继续使用原网站的自动切换最近球员逻辑；
- 使用原网站现有半透明、圆形、线性图标风格；
- 不新增 PNG、SVG 或字体资源，所有底盘、按钮和图标均用 Pixi `Graphics` 绘制。

原网站的 DOM/React 不能直接在微信小游戏运行，因此只替换表现技术，不改变按钮位置和操作含义。

## 3. 组件划分

### 3.1 `control-layout`

输入为逻辑屏幕宽高和安全区，输出摇杆中心、半径、五个按钮中心和点击半径。布局以原网站的 `132px` 摇杆与 `208px` 动作区为基准，根据横屏高度在 `0.75–1.0` 范围缩放，并避开左右安全区。

渲染层与命中检测必须读取同一个布局对象，禁止各自写一套坐标，避免“按钮看得到但点不中”。

### 3.2 `touch-input`

继续写入原版已经读取的共享对象 `__ORIGINAL_RUNTIME_SHARED_TOUCH_INPUT__`。每根手指按 `identifier` 独立跟踪角色：摇杆、挑传、传球、铲球、射门或冲刺。

- 摇杆持续写入 `vx/vy`，中心死区沿用原网站的 `0.18`；
- 射门、冲刺为按住状态，手指释放或取消后立即归零；
- 传球、挑传、铲球只在按下时产生一次脉冲，随后由原版比赛循环消费并清零；
- 支持左手移动与右手动作同时按下；
- 所有触摸结束、取消或应用失焦时，摇杆和按住状态必须清零；
- 控制层安装期间 `active` 保持为 `true`，确保原版循环能在松手后接收到归零输入。

首版不迁移双指缩放。微信小游戏中双指通常同时承担移动与动作，直接照搬网页的全局双指监听会与比赛控制冲突；镜头仍使用原版自动镜头。

### 3.3 `touch-controls-overlay`

使用 Pixi 4.8.9 `Container` 与 `Graphics` 创建固定屏幕坐标的控制层，在原版比赛触发 `B2_VISIBLE_MATCH_STARTED` 后添加到 `game.stage` 最上层。

覆盖层只负责绘制，不直接监听 Pixi Pointer 事件；微信 `wx.onTouch*` 仍是唯一输入源。摇杆帽位置从共享输入状态同步，按钮在按住时改变透明度或缩放，提供明确反馈。

当 renderer 尺寸或安全区改变时重新计算布局并重绘。覆盖层不得改变 stadium、camera 或 renderer 的 transform。

## 4. 数据流

```text
wx.onTouchStart / Move / End / Cancel
  → 按 identifier 分配触控角色
  → control-layout 统一命中检测
  → __ORIGINAL_RUNTIME_SHARED_TOUCH_INPUT__
  → 原版 acApplyInput
  → 原版 controller / player / physics

同一份 shared input + layout
  → Pixi touch-controls-overlay
  → 摇杆帽与按钮按压反馈
```

## 5. 启动与错误处理

- B1 之前只安装微信触摸监听，不创建 Pixi 控件；
- B2 比赛实例和舞台存在后创建覆盖层；
- 创建成功设置 `__ORIGINAL_RUNTIME_CONTROLS_VISIBLE__ = true`；
- 共享输入对象不是原版实际读取对象时继续使用现有 B1 硬失败；
- 覆盖层创建失败必须报 `B2_CONTROLS_FAILED`，不能静默退回隐形触区；
- 重复编译或热重载时先销毁旧覆盖层和旧监听，避免重复响应。

## 6. 验收标准

### 自动检查

- 布局渲染坐标与触摸命中坐标来自同一对象；
- 摇杆上、下、左、右及斜向输出正确，死区正确；
- 移动与动作支持双触点同时存在；
- 传球、挑传、铲球为单次脉冲；
- 射门、冲刺为按住状态并在释放后清零；
- 取消事件能清除全部连续输入；
- 工程仍通过无 `eval` / `new Function` 和包体静态检查。

### 微信开发者工具

- 原版比赛出现后，左摇杆与右侧五键清晰可见；
- 控件不遮住主要比赛区域，不受球场镜头移动影响；
- 开发者工具的诊断注入能让摇杆帽和按钮产生按压反馈；
- 控制覆盖层出现后仍保持 `B2_VISIBLE_MATCH_STARTED` 且控制台无新增错误。

### 真机

- iPhone 与 Android 横屏均能同时移动和执行动作；
- 松开摇杆后球员不会继续移动；
- 传球、挑传、铲球每次点击只触发一次；
- 长按射门与长按冲刺行为和原网站一致；
- 安全区、圆角和刘海不遮挡摇杆或动作键；
- 连续完成一整局，控制层无卡死、粘键或触摸丢失。

## 7. 明确不做

- 不引入 React、DOM 或 CSS 运行时；
- 不增加新的图片控制资源；
- 不修改原版比赛控制器接口；
- 不增加切人键；
- 不用不可见大触区冒充完整控制层；
- 不在本任务中压缩贴图或重排资源分包。

## 8. 2026-07-10 实测记录

- 自动测试通过：摇杆方向与死区、双指组合、动作单次脉冲、射门/冲刺长按、释放和取消清零。
- Pixi 覆盖层自动测试通过：摇杆底盘、摇杆帽、五个动作键、按压反馈和销毁流程。
- 微信开发者工具冷编译后，原版比赛与完整触控层同时可见，控制台错误数为 0。
- 运行时记录 `CONTROL_PIXI_RESOLVED version=4.8.9, Container=function, Graphics=function` 与 `B2_VISIBLE_MATCH_STARTED`。
- 桌面模拟器鼠标不能作为真实 `wx.onTouch*` 的可靠替代，因此真机手指输入仍属于未完成验收项。
- 多次热重载后开发者工具模拟器曾达到 1311.89 MiB 并触发其 1024 MiB 上限；重启后冷编译恢复。该现象不归因于约 0.02 MiB 的控制层代码，但必须在真机性能闸门中继续测量峰值内存。
