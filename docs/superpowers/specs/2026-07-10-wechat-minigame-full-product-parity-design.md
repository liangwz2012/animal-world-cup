# 微信小游戏全功能对齐设计

日期：2026-07-10  
唯一实施项目：`wechat-minigame-original-runtime-latest`

## 1. 目标

在已经跑通的原版 Pixi 4.8.9 比赛引擎、原版资源和微信触控基础上，把网页版现有的完整产品流程移植到同一个微信小游戏项目。不得新建替代项目，不得切换到简化比赛内核，不降低现有画面和资源质量。

最终流程固定为：

`品牌加载 → 选队与比赛设置 → 真人匹配（60 秒）→ 真人比赛或确认切换 AI → 比赛 HUD/操控 → 进球与半场反馈 → 全场结果 → 再来一局或返回选队`

## 2. 范围

### 2.1 启动与赛前

- 使用备案目录中的透明“动物足球赛”Logo。
- 绿色品牌背景与用户提供的参考图保持一致。
- 加载条显示真实分包加载进度，足球沿加载条从左向右滚动；静态模块初始化阶段从分包进度平滑补到 100%，不得倒退。
- 加载完成进入横屏双栏选队页。
- 复用网页版 8 支球队及头像：英格兰、法国、德国、西班牙、葡萄牙、巴西、阿根廷、美国。
- 左侧选择自己的球队，右侧选择对手；两边不能选择同一支球队。
- 可设置双方阵型、自己的主/客场球衣、AI 难度和比赛时长。
- 提供“真人匹配”“AI 对战”“观看 AI 对战”入口。
- 所有状态和选择留在当前项目内，不依赖网页路由。

### 2.2 真人匹配

- 真人模式为两名玩家各自在自己的手机进入微信小游戏，各控制一支球队的实时 1v1。
- 点击真人匹配后加入公共匹配队列；匹配条件至少包含版本、模式和区域，球队选择不阻塞配对。
- 等待 60 秒仍未匹配到真人时弹出“是否切换 AI 对战”。
- 点确认后退出队列并进入 AI 对战；点取消后继续等待真人，再过 60 秒可再次询问。
- 配对成功后服务端生成房间、分配红/蓝两方和权威主机，并同步双方球队与比赛参数。
- 网络采用 WebSocket。首版复用已有输入协议，但扩展心跳、序号、房间状态、快照和重连。
- 比赛采用主机权威：主机运行原版比赛并发送状态快照，客机发送输入并插值显示。严禁让两台设备各自独立模拟后只同步比分。
- 断线 3 秒内显示弱提示并自动重连；20 秒内重连成功则继续；超过 20 秒判定对手离开并允许 AI 接管或返回主页。
- 服务器不可用时不得假装匹配成功，明确显示网络错误并提供重试和 AI 对战。

### 2.3 比赛操控与镜头

- 保留现有左摇杆、挑传、传球、铲球、射门和冲刺键。
- 保留单人模式红队球员强制认领与 `B3_HUMAN_CONTROL_ACTIVE` 硬闸门。
- 双指张开时放大，双指捏合时缩小。
- 只有两根手指都从球场中央非控制区开始时才进入缩放；摇杆加动作键的双指组合不得触发缩放。
- 缩放沿用原引擎 `window.__matchZoom`，范围使用原接口限制，保持镜头平滑。
- 提供顶部放大、缩小和重置缩放按钮，兼顾不方便双指操作的玩家。
- 切到后台、电话中断或触控取消时，立即清零所有移动和按键状态，防止粘键。

### 2.4 比赛 HUD 与统计

- 顶部常驻比分条包含双方头像/标识、比分和比赛分钟。
- 比分条下方显示控球率；点击后展开射门、角球、界外球、球门球、铲抢和传球统计。
- 比分和统计只读取原版比赛对象与 `__matchStats`，不另算一套比赛结果。
- 工具区包含：放大、缩小、重置、截图、静音/开声、分享、返回主页。
- 第一次进入比赛显示可关闭的手机操作引导，之后本地记录已读。

### 2.5 进球、半场与声音

- 监听原版 `ab-goal`、比分变化、半场状态和 `ab-match-ended`。
- 进球时显示球队头像、进球文字和最新比分；同时播放球队配色纸屑、径向闪光和比分弹跳。
- 进球播放对应动物欢呼；比赛包含射门、传球、开球哨、终场哨、观众环境声和背景音乐。
- 小游戏音频使用 `wx.createInnerAudioContext` 或微信支持的音频上下文，不继续使用当前 no-op WebAudio 桩作为最终音频方案。
- 射门、进球和关键按钮提供可关闭的轻震动反馈。
- 半场显示简短卡片，不遮挡过久；动画结束后自动恢复操控。

### 2.6 赛后、主页与传播

- 全场结束页显示双方球队、最终比分、胜/负/平结论和完整统计。
- “再来一局”沿用当前两队和参数重新开赛。
- “返回主页”卸载当前比赛状态并回到选队页，不退出微信小游戏。
- 新比赛复用已经加载的引擎和资源，避免重复下载 9.77 MiB 分包。
- 截图使用 Pixi extract 或微信 Canvas 导出接口生成包含比分的图片。
- 分享使用微信小游戏分享能力，包含双方球队、比分或邀请信息；没有权限时清晰提示，不影响继续游戏。
- 保留网页版六语言资源并提供语言切换；中文为默认语言。

## 3. 技术架构

### 3.1 单项目状态机

新增宿主状态机管理以下状态：

- `loading`
- `home`
- `matchmaking`
- `match-loading`
- `playing`
- `halftime`
- `result`
- `network-error`

状态机只管理产品界面和流程；原版比赛状态仍由原引擎维护。两者通过稳定事件和参数对象通信，禁止 UI 直接修改内部球员物理状态。

### 3.2 渲染层

- 加载页使用与当前屏幕 Canvas 兼容的 WebGL 首屏渲染，复用旧项目已验证的首屏实现思路。
- 选队、匹配、HUD、庆祝和结果页均使用 Pixi 4.8.9 Container/Graphics/Sprite/Text，和原比赛共用同一渲染体系。
- 比赛启动后，HUD 与触控层挂到原版 `game.stage` 顶层，并在状态切换时维持正确层级。
- 所有坐标根据横屏尺寸、安全区和 renderer resolution 自适应。

### 3.3 参数模型

统一比赛配置对象：

```js
{
  redTeam,
  blueTeam,
  redFormation,
  blueFormation,
  side,
  ai,
  time,
  mode,
  roomId
}
```

原版 `__startStandaloneMatch` 从该对象取得参数，不再在 `start.js` 中硬编码阿根廷、葡萄牙、难度 2 和时长 2。

### 3.4 可重开比赛

构建期静态补丁向 standalone runtime 暴露安全的重新开赛入口：退出当前 StandaloneMatch、卸载球场、使用新配置重新进入同一状态。返回主页时暂停并隐藏球场，显示宿主页；再次开赛时复用 renderer、纹理与资源索引。

## 4. 错误处理

- 分包下载失败：加载页保留，显示重试，不弹重复致命弹窗。
- 原版模块或首帧失败：保留现有 B1/B2 硬失败诊断。
- 玩家绑定失败：保留 B3 硬闸门，但界面改为可理解的“操控初始化失败，点击重试”。
- 网络失败：退出匹配队列，提供重试、切换 AI 和返回主页。
- 图片或音频单项失败：使用无损主流程的占位或静音降级，并记录明确日志。
- 所有弹窗去重，同一故障只出现一次；普通 Pixi 弃用警告不显示为“不兼容”。

## 5. 实施顺序

1. P1：宿主状态机、品牌加载页、选队/阵型/难度/时长、比赛参数化、返回主页。
2. P2：比分/统计 HUD、双指缩放和按钮缩放、进球/半场/赛后页、可重开比赛。
3. P3：音效、震动、截图、微信分享、多语言、AI 观战。
4. P4：公共真人匹配、60 秒转 AI、主机权威同步、断线重连和失败降级。

四期都在同一个项目连续完成；每期通过后继续下一期，不创建并行替代项目。

## 6. 验收与测试

### 自动测试

- 加载进度单调递增，足球位置与进度一致。
- 8 支球队、同队互斥、阵型、球衣、难度和时长参数映射正确。
- 返回主页、再来一局和新配置开赛状态转换正确。
- 摇杆＋动作键双指不触发缩放；中央球场双指正确改变缩放。
- 比分、时间、统计、进球、半场和终场事件映射正确。
- 静音、音频失败、截图失败和分享失败不阻断比赛。
- 匹配成功、60 秒超时、确认转 AI、取消继续等待、断线重连和超时判负/AI 接管均有协议测试。

### 开发者工具验收

- 普通编译 0 个当前错误。
- `B2_VISIBLE_MATCH_STARTED` 与 `B3_HUMAN_CONTROL_ACTIVE` 同时出现。
- 加载、选队、比赛、结果、返回主页可循环两次以上。

### 真机验收

- iOS 与 Android 各完成至少一整局 AI 比赛。
- 两台真机完成一整局真人对战并测试一次断网重连。
- 验证双指缩放、摇杆加动作键、后台恢复、音效、震动、截图和分享。
- 记录首次加载时长、峰值内存、平均/最低帧率与发热情况。
- 主包低于 4 MiB，所有包总量低于 20 MiB；普通资源分包保留当前合法结构。

## 7. 完成定义

只有在唯一最新版项目中完成上述全流程、自动检查通过、开发者工具完成两轮循环、两台真机完成真人对战，并且不存在简化比赛回退，才称为“全部做完”。
