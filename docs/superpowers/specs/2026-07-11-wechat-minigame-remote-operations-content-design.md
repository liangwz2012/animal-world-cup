# 微信小游戏远程运营配置与内容目录设计

## 目标与边界

在不下载或执行远程代码的前提下，让《动物足球赛》已预置的运营参数和内容模板可以从服务端更新。首期支持远程调整免费局数、解锁奖励和分享时间阈值，并为后续增加球队、动物外观、球衣、饰品、足球、音效和海报建立统一内容目录。

远程系统只能改变客户端已认识的字段和素材。新增游戏逻辑、页面结构、权限、多人网络协议、支付、陌生资源格式或可执行脚本，仍需更新小游戏代码版本。

## 子系统拆分

### RemoteOperationsConfig

负责小体积、强校验的运营参数。客户端启动时通过 `wx.request` 拉取 JSON，超时、返回异常或校验失败时立即使用代码包内置默认值，不阻塞首屏和比赛。

首版字段：

```json
{
  "schemaVersion": 1,
  "policyVersion": 1,
  "publishedAt": "2026-07-11T00:00:00Z",
  "initialFreeMatches": 2,
  "unlockRewardMatches": 2,
  "shareReturnCheckMs": 2000,
  "rewardedAdEnabled": true,
  "rewardedAdUnitId": "",
  "contentCatalogUrl": ""
}
```

允许远程调整的数值必须经过白名单和范围约束：

- `initialFreeMatches`：1–20，默认 2。
- `unlockRewardMatches`：1–20，默认 2。
- `shareReturnCheckMs`：1000–10000 毫秒，默认 2000。
- 布尔开关只接受严格布尔值。
- URL 只接受预先允许的 HTTPS 域名，不接受 `javascript:`、`data:`、IP 地址或临时跳转域名。
- 未知字段全部忽略，远程响应不能覆盖任意客户端对象。

客户端缓存最后一次校验通过的配置。启动优先级为：内置默认值 → 本地有效缓存 → 后台刷新成功的新配置。刷新失败继续使用缓存或默认值。

### RemoteContentCatalog

负责内容数据和静态素材引用，不负责运营计数。目录按版本发布，客户端只处理已内置支持的内容类型。

```json
{
  "schemaVersion": 1,
  "catalogVersion": "2026.07.11.1",
  "minimumClientContentVersion": 1,
  "teams": [],
  "animals": [],
  "kits": [],
  "accessories": [],
  "balls": [],
  "audio": [],
  "posters": []
}
```

每项内容包含稳定 ID、简体中文显示名、启用状态、资源版本、文件地址、文件大小和 SHA-256 校验值。球队可以引用动物、主客场球衣、头像、队徽和预设阵型；动物外观可以引用身体、头部、衣服和饰品图层。

首期只开放已支持模板：

- 球队元数据与头像替换。
- 动物头像/头部图片替换。
- 球衣和静态饰品图片替换。
- 已支持尺寸和帧结构的精灵图替换。
- 足球、海报、背景和音效替换。

不允许目录声明新的 JavaScript、WASM、Shader 程序、模板表达式或可执行脚本。

## 资源分层和组合

角色资源采用稳定的分层槽位，而不是让远程目录任意改变渲染结构：

1. `body`：基础身体。
2. `head`：动物头部或头像。
3. `kit`：球衣。
4. `accessory`：帽子、围巾等静态饰品。

每个槽位有固定锚点、允许尺寸和透明 PNG/WebP 规则。原引擎仍使用客户端内置的动画、骨骼、碰撞和玩法代码；远程内容只替换槽位纹理。需要新动画帧布局或新锚点规则时必须升级客户端。

## 下载、缓存和回退

- 运营配置使用 `wx.request`；大图片、图集和音频使用 `wx.downloadFile`。
- 请求域名与下载域名必须在微信后台预先配置，使用完成 ICP 备案的 HTTPS 域名。
- 下载资源写入微信用户文件目录，缓存索引记录内容 ID、版本、路径、大小、校验值和最后使用时间。
- 同时下载最多 3 个资源，避免占满微信网络接口并发额度。
- 下载完成后核对 HTTP 状态、文件大小和 SHA-256；不通过时删除文件并使用内置资源。
- 目录切换采用“完整下载后原子启用”，不能让同一场比赛混用新旧半套资源。
- 本地缓存达到预算时按最近最少使用清理；八支基础球队、基础球和品牌 Logo 保留在代码包中，永不依赖网络。
- 比赛过程中不热替换角色纹理；新版本从下一次进入选队页或下一场比赛生效。

## 免费局数策略迁移

本地局数状态增加 `appliedPolicyVersion` 和 `policyInitialFreeMatches`。

- 新玩家第一次初始化时使用当前远程 `initialFreeMatches`。
- `policyVersion` 未变化时不重复发放初始局数。
- 新策略把初始局数从 2 提高到 5 时，老玩家剩余局数补足到至少 5，但不重复累加差额。
- 新策略把初始局数从 2 降到 1 时，不扣减老玩家已有局数；新玩家从 1 局开始。
- 同一个 `policyVersion` 修改初始局数不会再次迁移，服务端每次需要触发迁移时必须发布更高的 `policyVersion`。
- 广告/转发奖励使用当前 `unlockRewardMatches`，只影响奖励发生后的新记录，不追溯历史奖励。

## 发布与回滚

- 运营配置和内容目录分别版本化，可以独立发布和回滚。
- 服务端保留当前版本和上一个稳定版本；发现异常时只切换指针，不覆盖旧文件。
- 配置支持 `publishedAt` 和可选生效时间，但客户端时间异常时仍以服务端返回顺序和版本号为准。
- 新目录先灰度到内部测试账号，再扩大比例；首版客户端即使不支持灰度字段也必须安全忽略。
- 每次发布生成不可变资源 URL，禁止在相同 URL 下静默替换不同文件。

## 审核和内容安全

远程更新减少代码包发布次数，不代表远程内容免于平台监督。所有远程球队、动物、球衣、头像、饰品、音频和文案必须具备合法版权并符合微信小游戏内容规范。

不得在审核期间隐藏核心功能后远程开启违规功能，也不得通过配置下载或拼接远程代码。新增多人对战、好友头像、用户内容、支付、排行榜、相册/隐私权限等实质性能力，必须单独评估是否更新隐私声明、平台配置和提审版本。

## 诊断与监控

客户端记录但不上传敏感信息：

- 当前配置来源：默认、缓存或网络。
- 配置版本和内容目录版本。
- 最近一次下载失败类型。
- 缓存命中率与已用空间。
- 当前局数策略版本和迁移结果。

远程服务记录配置/目录请求成功率和版本分布。任何配置解析异常不能弹出阻塞游戏的系统弹窗，只在诊断区记录并回退。

## 测试要求

- 无网络、超时、HTTP 非 2xx、非法 JSON 和未知字段均安全回退。
- 数值越界、非 HTTPS URL、未允许域名和错误校验值被拒绝。
- 2→5 补足、2→1 不扣减、同版本不重复迁移。
- 新配置不会阻塞首屏，刷新完成后只影响下一次动作。
- 新目录完整下载前继续使用旧目录；下载中断不会留下半套可见内容。
- 缓存资源丢失或损坏时自动退回代码包资源。
- 新球队和换装内容不改变碰撞、阵型、操控和原引擎玩法。
- Android、iOS、PC 微信和开发者工具均验证配置请求、下载缓存与离线回退。

## 实施顺序

1. 在免费局数功能中实现配置白名单、缓存和策略迁移。
2. 接入广告/分享奖励，使局数和 2 秒阈值来自有效配置。
3. 建立内容目录解析、下载缓存和内置资源回退。
4. 先把现有八支球队纳入同一内容模型，证明本地与远程来源可以无差别使用。
5. 再开放新增球队、动物分层、球衣和饰品的运营发布流程。
