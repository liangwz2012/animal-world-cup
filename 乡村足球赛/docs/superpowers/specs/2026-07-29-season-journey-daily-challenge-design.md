# 乡村足球赛：赛季征程与每日挑战（首发版）

日期：2026-07-29

## 决策

首发版本采用通俗、低学习成本的玩法闭环：**赛季征程 + 每日挑战 + 现有排行榜**。

不在首发版本加入“兽魂连携”“野性翻盘”、技能树、动态球场规则或数值养成。这些内容统一归入第二阶段的留存升级包，只有在首发流量和留存开始下滑后再制作与投放。

## 首发目标

- 玩家第一次打开就能理解：选球队、打比赛、赢球推进赛季、每天有一关可挑战、成绩可在排行榜查看。
- 保持现有横版 16:9 界面与比赛操控，不改动底层比赛运行时。
- 默认只保存在本机；不主动登录、不读取头像昵称、不新增隐私信息处理。
- 赛季和每日挑战的成绩进入既有本机统计。全服榜在已部署、已配置合法域名且玩家主动加入排行榜后再接通。

## 玩法设计

### 赛季征程

1. 首页新增“赛季征程”入口，显示当前轮次、积分和下一场对手。
2. 一个赛季固定为 5 场单人 AI 比赛，按既有比赛时长和难度配置运行。
3. 胜 3 分、平 1 分、负 0 分；同分时依次按净胜球、进球数排序。
4. 完成 5 场后结算为冠军、亚军或完成赛季，并保存历史最佳名次；玩家可以开始下一赛季。
5. 中途退出不记为赛果，重新进入时从下一场未完成比赛继续。已结算赛果不可重复计分。

首发只做一条固定赛程和 AI 对手，不做抽卡、体力、付费解锁或随机事件。

### 每日挑战

1. 首页新增“每日挑战”入口，显示当天主题、对手和当日最佳成绩。
2. 每个自然日生成一条固定挑战配置：固定对手、难度、比赛时长与目标分数；所有本机当天进入的玩家看到相同规则。
3. 每天可不限次数重试，仅保存当天最佳成绩。
4. 排名口径依次为：是否完成目标、净胜球、进球数、完成所用时间；完全相同则以较早达成的记录优先。
5. 跨天自动切换新挑战，保留过去 7 天的本机历史供玩家查看。

首发不把每日挑战强制绑定分享、广告或登录。后续服务端上线后，沿用相同的挑战编号与排序口径接入全服每日榜。

### 排行榜和隐私边界

- 继续保留已有积分、胜场、进球、胜率、净胜球和连胜等指标入口。
- 赛季征程与每日挑战会更新本机统计；普通对局仍按现有规则记录。
- 在未配置线上服务时，排行榜明确显示为本机战绩，不展示虚构玩家或虚构名次。
- 仅当玩家主动点“加入排行榜”时，才走既有的头像、昵称及登录流程；首发玩法本身不触发这些权限。

## 技术边界

新增代码限定为以下独立模块，避免把赛季逻辑塞进比赛运行时：

```
src/data/season-journey.js       赛程、积分、持久化、结算
src/data/daily-challenge.js      日期规则、最佳记录、7 天历史
src/app/main.js                  根据模式组织比赛参数和赛果回写
src/ui/game-shell.js             横版入口、进度卡和赛后结果展示
tools/test-season-journey.mjs    赛季积分与断点续玩测试
tools/test-daily-challenge.mjs   日期、排序和跨日测试
```

两个数据模块只暴露“读取快照、开始比赛、记录赛果、重置下一赛季”的清晰接口。它们依赖现有微信本地存储适配层；存储不可用时降级为当前运行会话，不阻断比赛。

## 赛果与异常处理

- 只有比赛运行时返回合法终场结果时才允许赛季或每日挑战结算。
- 重复回调、缺失比分、未知模式和已结算轮次必须忽略，不能重复加积分。
- 本机日期异常时，使用上次成功日期对应的挑战并提示“日期暂不可用”；不伪造新日期。
- 更新失败时保留旧快照并记录诊断日志，不影响玩家继续开赛。

## 验收标准

1. 新玩家可在三步内进入赛季第一场；完成一场后首页轮次和积分立即更新。
2. 五场赛季的积分、同分排序、冠军结算、退出后续玩和下一赛季重置均正确。
3. 同一天内每日挑战规则稳定、多次挑战只保留最优记录；跨天生成新挑战并能查看最近 7 天记录。
4. 首发默认不会调用登录、头像或昵称接口；未接线上服务时不会出现虚构全服排行榜。
5. 现有普通开赛、排行榜抽屉、好友对战开关及所有构建测试继续通过。

## 第二阶段：流量下滑后的留存升级

届时再评估并独立设计“野性翻盘”版本：90 秒快节奏模式、动物连携、高光回放和差异化球场。该阶段需要单独验证内容产能、平衡成本、留存收益与全服榜反作弊，不能提前混入首发赛季逻辑。
