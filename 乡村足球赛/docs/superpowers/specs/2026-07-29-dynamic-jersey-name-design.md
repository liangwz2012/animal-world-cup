# 动态乡村队服文字框架

## 目标

保留现有比赛引擎、物理、AI、操作和联机同步不变。赛前根据省份、城市/县、乡镇/街道、村名或自定义队名，在本地为双方生成胸前与背后的队服文字；贴图进入原有球衣纹理槽，因此随原角色骨骼、旋转和镜头缩放一起渲染，不出现悬浮文字。

## 范围

- 仅处理现有八支队伍的主场、客场、守门员 `shirt_front.png` / `shirt_back.png`。
- 赛前将原球衣图片绘制到同尺寸 Canvas，再叠加受限文字并注册为 Pixi 纹理。
- 缓存键包含队伍、套装、胸前文字和背后文字；相同配置不重复绘制。
- 内置全国 34 个省级、337 个地市、3,285 个县区；41,278 个乡镇/街道放在 `region_data` 普通分包，仅在选择乡镇时加载。
- 地名只保存在本机比赛配置中；不联网、不读取微信昵称、头像或设备位置。

## 名称规则

- 自定义队名始终优先。未手填时可从完整行政区快照选择任意一个层级，或选择一对相邻父子层级；球衣仅展示最终选中的更细一级，例如 `广东省 + 广州市` → `广州`、`信宜市 + 镇隆镇` → `镇隆`。
- 村名、自然村和自定义队名保留自由输入；不将六十多万条村级清单放进小游戏包体。
- 胸前采用 2--4 个字的简称；背后采用 2--6 个字的简称。原引擎的球员号码层保持不变，下一轮再开放号码自定义。
- 输入会去除首尾空白、控制字符和不适合作为队名的符号；超长名称按视觉宽度缩小后截断。
- 不生成真实政府徽标、赛事标志或对外联网内容。

## 渲染方案

1. 创建同原始球衣尺寸的离屏 Canvas。
2. 先绘制本地的原球衣底图，再以居中、描边、阴影文字写入胸前或背后安全区域。
3. 将 Canvas 导出的本地图片注册到既有图片加载适配层，再替换当前队伍的球衣路径。
4. 在 `__startStandaloneMatch` 的队伍集合加载后、球员皮肤合成前完成纹理路径替换；原游戏创建球员时仍按原有骨骼与图片槽位读取，因此不修改角色骨骼、碰撞和输入逻辑。
5. 任何绘制或图像加载失败时回退原始球衣，不阻断比赛启动。

## 验收

- 自定义“石桥村”“稻香队”等名称可生成稳定的胸前和背后贴图。
- 主场、客场、守门员三套均有独立缓存键。
- 同配置再次开赛复用缓存；更换队名时重新生成。
- 文本模块可在 Node 假 Canvas 下测试；现有 `npm run check` 继续通过。
- 不增加网络、登录、广告、运行时动态代码或任何游戏物理修改。

## 风险与回退

- 微信 Canvas 或本地图像在个别机型加载失败时，仅回退原球衣并记录诊断，不影响开赛。
- 首轮不增加赛前输入控件，默认以“镇隆 / 广州”展示可见样例，并提供程序化配置与诊断入口；待真机确认纹理路径稳定后再接入 UI。
