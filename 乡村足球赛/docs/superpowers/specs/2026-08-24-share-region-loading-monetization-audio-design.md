# 地域分享继承、82% 加载、广告门槛与暂停音频设计

## 背景与目标

《乡村足球赛》首发候选版已经具备地区选队、地域转发标题、远程配置、激励广告适配器和比赛暂停。当前仍有四个需要收口的问题：

1. 首局从 82% 进入比赛时等待明显；
2. 地域对阵分享只展示标题，接收者仍需重新选择省、市、县；
3. 两局后的商业化入口需要预埋，但首发必须关闭且不能形成强制分享；
4. 暂停比赛时背景音乐和人群环境声仍继续播放。

目标是在不申请定位权限、不改变现有行政区数据库、不破坏好友邀请和首发离线可玩的前提下，完成可测试、可回退的状态链。

## 方案比较与选择

### 82% 加载

- 方案 A：只调整进度文案。实现最简单，但不缩短真实等待，拒绝采用。
- 方案 B：继续扩大图片 base64 预热。可以减少文件读取，但无法消除 `fans.load` 与 `game.load` 串行等待，单独使用不足。
- 方案 C（采用）：让观众资源加载与比赛资源加载并行，但用双就绪屏障保证两者都完成后才进入比赛状态。这样总等待由两段耗时相加变为取较慢者，同时不重演“分包未落盘就加载 AMD/i18n”的启动顺序错误。

若方案 C 在低端真机仍不达标，再单独立项做构建期观众图集预烘焙；本里程碑不把高风险离线渲染器塞入发布链。

### 地域分享

- 方案 A：分享完整中文名称。参数可读，但容易被伪造且名称变化难兼容，拒绝采用。
- 方案 B（采用）：只携带版本号和行政区代码前缀，启动后用本地行政区数据重新解析名称。
- 方案 C：上传短链接到服务器。需要在线服务和数据库，不适合首发离线链路。

### 商业化门槛

- 方案 A：两局后必须分享或看广告。存在诱导分享和用广告阻断正常服务的审核风险，拒绝采用。
- 方案 B（采用）：客户端保留已审核的激励广告与场次门槛代码，首发远程总开关关闭；未来只有在有效广告位存在时云端才能开启广告奖励。分享只承担邀请和地域传播，不计解锁奖励。
- 方案 C：首发直接开启广告。当前没有正式广告位 ID，也未完成广告组件审核，不采用。

## 架构与数据流

### 1. 地域分享上下文

新增独立模块 `src/data/share-region-context.js`，职责仅包括编码、解析和验证前的结构归一化。

分享参数格式：

```text
rfv=1&rh=440000.440900.440983
```

- `rfv`：协议版本；
- `rh`：省、市、县行政区代码，最多三级；
- 不包含中文名称、自定义村名、用户标识、定位信息或其他隐私字段；
- 如果发送者已选到乡镇，分享时去掉乡镇叶子，只传播其省、市、县前缀；例如“广东省→茂名市→信宜市→镇隆镇”传播为 `440000.440900.440983`；
- 如果只选到省、市或县，则传播当前已选择的有效前缀。

接收流程：

1. `getLaunchOptionsSync` / `onShow` 读取查询参数；
2. 好友房间邀请参数优先，好友对战仍使用房间冻结配置；
3. 普通地域分享调用 `createRegionTeamSelection` 验证代码链；
4. 验证通过后覆盖当前会话的主队地区，并写入既有家乡队本机缓存；
5. 自动重新生成同层级客队；用户可以继续选择下一级，也可以主动改到其他地区；
6. 用户后续分享始终读取当时最新的主队地区，形成新的传播链。

非法版本、超长参数、非数字代码、断裂父子关系或本地数据库不存在的代码全部静默忽略，回落到本机上次选择。

### 2. 82% 双就绪屏障

保持以下启动硬顺序不变：

```text
runtime-assets 分包落盘 → region_data 分包落盘 → AMD/i18n 模块加载
```

仅修改进入单场比赛后的资源阶段：

```text
              ┌─ fans.load ───────┐
startMatch ───┤                    ├─ 双就绪屏障 ─ states.change ─ 首帧
              └─ game.load ───────┘
```

- 两个加载任务同时开始；
- `game.load` 可以持续上报 82%–96% 的真实资源进度；
- `fans.load` 完成后记录观众就绪；
- 两者都完成才允许 `states.change`，因此比赛状态不会读取未完成的观众图集；
- 观众超过 12 秒仍未完成时沿用现有安全降级：本局无动态观众但比赛继续；
- 加入分阶段耗时日志：`fansMs`、`gameMs`、`barrierMs`、`firstFrameMs`，用于开发者工具和真机判断真正瓶颈；
- 不并行分包和 AMD 模块加载，避免再次出现 `Unknown language code: en`。

### 3. 云端广告门槛

沿用现有 `remote-config`、`play-gate` 和 `rewarded-ad`：

- 首发默认：`enabled=false`、`playGateEnabled=false`、`adUnlockEnabled=false`、广告位 ID 为空；
- 云端只有同时满足总开关、场次开关、广告开关和合法 `adunit-...` ID 才能启用；
- 每日免费场次数默认 2，可由远程配置在安全范围内调整；
- 完整观看激励视频才发放额外场次；提前关闭不发奖励；
- 分享不解锁场次，`SHARE_UNLOCK_ENABLED` 保持 `false`；
- 没有广告、广告加载失败或远程配置异常时不得锁死玩家，保持首发无限畅玩或回落到非商业化状态；
- 是否允许后续远程开启仍以微信广告位审核和当时平台规则为准，不在客户端声称“无需再次审核”。

### 4. 暂停音频

`SoundBank` 增加幂等暂停状态：

- `pauseMatchAmbience()`：对正在播放的 `music` 与 `crowd` 循环调用 `pause()`，保留当前播放进度；
- `resumeMatchAmbience()`：仅在未静音且确实由比赛暂停挂起时调用 `play()`；
- `stopMatchAmbience()`：仍销毁上下文，离开比赛不保留进度；
- 单次哨声、踢球声不在恢复时重放；
- 比赛暂停按钮、好友房主同步暂停和外部 `setPaused` 最终都通过同一状态同步函数控制音频；
- 好友客机不能修改比赛权威暂停状态，但收到房主暂停状态后本地音频同步暂停。

## 错误处理与兼容性

- 地域分享解析失败：记录一次简短告警并使用本机缓存，不弹错误框；
- 分享参数与好友房间参数并存：好友房间优先，避免覆盖冻结阵容；
- 观众加载失败：12 秒后降级无观众，比赛资源完成后正常进入；
- 比赛资源失败：继续走现有启动致命错误上报，不被观众降级吞掉；
- 音频上下文不支持 `pause/play`：安全忽略，不影响比赛暂停；
- 旧分享链接没有 `rfv/rh`：行为保持不变。

## 测试与验收

### 自动测试

1. 地域参数编码、乡镇叶子剥离、三级上限、非法代码与版本拒绝；
2. 分享启动覆盖本机缓存、用户改选后新分享更新、好友邀请优先；
3. `fans.load` 与 `game.load` 确实同时启动，任一未完成不得进入状态；
4. 观众超时降级后比赛仍可进入；
5. 暂停/继续音乐和人群声保留进度，静音状态不被继续操作破坏；
6. 云端广告四条件硬门、无广告失败开放、分享解锁持续关闭；
7. 完整 `npm run release:check` 通过。

### 开发者工具与真机验收

- 冷启动后立即开赛与在首页停留 5 秒后开赛各测一次；
- 记录 82% 到首帧耗时，并确认进度不再长时间固定在 82%；
- 从“信宜镇隆”分享打开后，主队应预填到“广东→茂名→信宜”，乡镇可继续选择；
- 改选“广东→东莞→厚街”后再次分享，新接收者不再得到茂名前缀；
- 暂停 5 秒期间比赛时间、音乐和人群声都停止，继续后从原位置恢复；
- 广告总开关关闭时连续多局不出现广告或解锁面板。

## 非范围与停止条件

本里程碑不申请定位权限、不接入人脸/头像生成、不购买广告、不修改线上远程配置、不部署服务、不提交审核。完成条件为代码、专项测试、完整发布门禁和开发者工具验收全部通过；真机广告播放与后台流量主资格由账号所有者在具备正式广告位后验收。
