# 比赛体验与公平性收口设计

> 日期：2026-08-23
> 状态：原型已由用户确认，进入实现

## 目标

在不改变七人制核心规则、阵型参数、传球/射门手感和联网数据合同的前提下，完成首发前一批可复现的比赛体验修复：精简工具栏、提供本地暂停、放大并疏开右手操作区、让冲刺有可感知效果、修复下半场场边队名、球员体型错配、球衣文字镜像和客队门将被二次削弱。

## 范围

1. 首页不增加第二个分享按钮；在微信右上角系统菜单旁显示“点击右上角 ··· 转发分享”的轻提示。
2. 比赛左上工具栏保留缩小、放大、主页、声音、截图、分享；删除复位、按键调整和信息按钮。
3. 比分栏右侧增加明显的暂停/继续按钮。单机局可暂停；好友客机不得单方面改变权威比赛状态。
4. 右手五个动作键直径增大、间距放宽，保留“上挑、左传、中射、右冲、下铲”的既定对应和触控语义。
5. 冲刺必须同时满足方向输入与按住“冲”：无球保持 17→21 km/h；持球由 14→17 km/h，不提升到无球冲刺上限。
6. 场边队名牌整体上移；进入下半场时主客队名牌随场地实际换边。
7. 球员视觉体型按真实主客队名单映射，不再用运行时槽位对双方套同一序列，修复 5 号被误套高瘦体型造成的颈身比例问题。
8. 球衣地区文字根据胸衣完整父级变换判断镜像，保证所有跑动方向下汉字始终正向。
9. 移除客队门将的二次 20% 降速，并取消双方门将的全局移动/拦截削弱，恢复原引擎一致的门将响应；普通客队场上球员仍沿用现有简单难度平衡。

## 非范围

- 不新增强制分享、分享换场次或分享奖励；首发场次闸门保持关闭。
- 不重写传球、射门、碰撞、阵型或普通 AI 决策。
- 不在本里程碑重做球员美术、观众或球场场景。
- 不变更排行榜、好友房间和生产数据库协议。

## 技术边界

- 可维护源码只改 `src/`、`tools/` 与 `source-assets/`；`generated/`、`runtime-assets/`、`shell-assets/` 由构建生成。
- 原引擎修复通过 `tools/build.mjs` 的唯一命中字符串补丁完成，并用生成包断言防止上游压缩产物变化后静默失效。
- 暂停按钮调用现有 `pitch.pause/resume` 或匹配同步桥；好友客机仅提示由房主控制，不启动第二套状态。
- 体型只改变 Spine 视觉根节点与球衣接缝，不改变碰撞、速度和足球尺寸。

## 验收标准

1. 首页只有挑战玩法、立即开赛、战绩与好友三个底部按钮，并出现右上角转发提示。
2. 比赛工具栏恰好保留六项；暂停/继续可反复切换，返回主页与截图/分享不受影响。
3. 五个动作键在 1280×720 和窄横屏上不重叠、不越过安全区，双指“摇杆+冲刺”仍可同时命中。
4. 构建产物包含持球冲刺分支；普通移动冲刺参数保持不变。
5. 下半场测试中红蓝队名牌位置互换且整体高于旧版。
6. 14 名球员体型序列与真实红蓝名单逐一对应；5 号为 `tall-strong`。
7. 父级骨架翻转但胸衣局部缩放不变时，球衣汉字仍保持正向。
8. 构建产物不再包含全门将削弱，蓝队二次削弱明确排除门将。
9. 所有新增专项测试及 `npm run release:check` 通过；开发者工具完成首页、开赛、暂停、上下半场名牌和操作区实测。
10. 构建完成后逐个执行主包与分包 JS 语法检查，禁止微信把生成语法错误伪装成“module is not defined”后进入上传包。

## 回滚

所有变更限定在本项目目录并由单次提交承载；若真机出现手感回归，可整体回退该提交。冲刺和门将修复均由构建期唯一命中补丁控制，可单项恢复而不影响 UI。
