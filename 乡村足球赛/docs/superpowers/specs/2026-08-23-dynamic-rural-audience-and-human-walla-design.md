# 原生动态村民观众与人群环境声设计

## 背景与根因

原生电脑网页版的观众不是一张围场图。`stadium.json` 保存 2342 个座位坐标和 `fansmask.png` 遮罩，`fans` 模块使用人物骨骼、种族皮肤和随机球衣生成观众，再挂到球场世界层。

小游戏旧适配曾为规避 120 套 8x RenderTexture 造成的长卡和高 GPU 内存，把该系统整体关闭，改用 4096×2048 静态观众图。该图由四边重复拼接，存在断口、错向、镜头裁不到和不会动等问题。

## 方案比较

1. **继续修静态大图**：首帧最轻，但角度、断口和动作无法根治，已弃用。
2. **四条独立方向观众**：方向可控，但四角仍有接缝，且需要人工排座，不采用。
3. **恢复原生座位观众（采用）**：沿用网页版坐标、遮罩、镜头和人物骨骼，只替换为村民皮肤并做移动端内存收敛。

## 实现设计

- 保留 2342 个座位和原 `fansmask.png`，因此观众位置、四边覆盖、镜头缩放与遮挡都与原生网页版一致。
- 观众种族白名单仅允许 `rural_01`–`rural_14`，不传入旧动物种族。
- 生成 24 套村民皮肤，随机球衣、短裤和球袜颜色，复用到全部座位。
- 人物纹理由 8x 降为 4x；每套生成两个 `sitting` 动作帧，约占原高清方案十分之一的 GPU 内存。
- 观众按随机相位切换双帧，每四人中一人做微小上下摇摆，避免 2342 人同步动作和每帧全量更新。
- 观众加载仍保留 12 秒超时降级；极端低端设备无法完成时先进入比赛，不因观众阻断玩法。
- 静态 `rural_crowd.png` 从源资源和运行分包移除，不再存在双层观众。

## 人群环境声

- 环境声替换为 Selector 的 CC0 人群录音。
- 经高/低通、错位叠加、轻回声和压缩处理，保留“有人在说话”的环境感，但听不清任何具体句子。
- 运行规格为 44.1 kHz、立体声、64 kbps MP3，约 242 KiB。
- 进球欢呼、哨声、踢球和撞柱声保持独立，不被环境声覆盖。

## 验收

- 运行球场含 2342 个座位、14 个村民种族、24 套复用皮肤和 4x 纹理上限。
- 构建产物不含 `rural_crowd.png`，球场精灵不挂静态 `fans.png`。
- 微信开发者工具实际开局后能看到多排村民观众，连续截图的看台区域存在帧差。
- 主包低于 4 MiB，资源分包和总包低于微信限制。
- 静态门、动态观众专项测试和完整 `npm run release:check` 通过后才可上传。
