# 接球控制权、真实进球头像与加载提示设计

## 背景与目标

版本 `1.0.10` 上传后发现两个比赛问题：上半场部分队友接球后用户无法操控，但下半场换边后恢复；进球庆祝弹窗始终使用固定队长头像，而不是真实进球队员。加载页还需要在真实等待期间轮换简短提示，避免用户误以为卡死。

本次目标是修复控制权不变量、把真实进球队员身份传递到 HUD，并增加加载提示轮换。不得改变传球、切人、AI、速度、碰撞、比赛时长和上下半场换边参数。

## 根因

### 控制权

原版适配层的 `acDriveClaim` 在 `user.team` 存在时立即返回，隐含假设“用户属于球队就一定拥有有效的 `user.player`”。传球、接球或状态切换期间，原引擎会出现保留 `user.team` 但暂时释放 `user.player` 的中间状态。下一帧适配层不再认领球员，导致输入仍写入控制器却没有目标。下半场换边重新绑定用户，因此症状暂时消失。

### 进球头像

`Goal.onEnter` 已经能获得实际触球球员，但适配层发出的 `ab-goal` 事件只包含主客队 ID 和比分。HUD 因此只能按球队固定选择返乡大学生或客队队长头像。

## 方案比较与选择

### 控制权

- 方案 A：只在半场切换时重新绑定。不能解决上半场中途丢失，拒绝采用。
- 方案 B：每帧强制控制持球队员。会覆盖用户主动切人，拒绝采用。
- 方案 C（采用）：维护最小控制权不变量。用户球队错误时修正球队；当前球员为空、已失效或不属于球队时才重新认领；队友接球时沿用既有自动切人算法，不改变手动切人优先级。

### 进球头像

- 方案 A：继续按球队展示队长。信息错误，拒绝采用。
- 方案 B（采用）：进球事件传递全局球员 ID、球员所属侧和得分侧，HUD 通过固定14人比赛名单映射到对应头像；事件缺少有效身份时才回退队长。

## 设计

### 1. 控制权不变量

修改生成适配代码中的 `acDriveClaim`：

1. 非活球时维持原释放逻辑；
2. 活球时如果 `user.team !== team`，调用 `changeTeam(team)`；
3. 只有 `user.player` 存在、仍属于目标球队且没有被移出比赛时，才允许提前返回；
4. 无有效受控球员时优先认领本队非门将持球人，否则认领离球最近的非门将；
5. 调用 `takeControl` 后写入诊断计数和原因；
6. 原有 `acAutoSwitch`、手动切人、输入脉冲、门将排除和好友客机只渲染规则保持不变。

控制状态诊断增加：有效用户、有效球队、有效受控球员、重认领次数及最近原因。连续比赛和上下半场都能在开发者工具中核验。

### 2. 真实进球队员头像

`Goal.onEnter` 事件增加：

```text
scoringSide  得分方 red/blue
scorerSide   实际触球球员所属方 red/blue
scorerId     原引擎全局球员 ID，红方0–6、蓝方7–13
ownGoal      是否乌龙
```

HUD 引入 `RURAL_MATCH_LINEUP_INDEXES`：

- 红方本地序号 = `scorerId`；
- 蓝方本地序号 = `scorerId - 7`；
- 本地序号映射到固定比赛名单，再读取 `shell-assets/squad/<player-id>.png`；
- 弹窗头像使用真实球员；彩带颜色仍使用得分方球队颜色；
- 乌龙球显示实际触球球员头像，但彩带和比分按得分方；
- 好友客机或旧事件没有 `scorerId` 时回退对应球队队长头像，不阻断庆祝。

### 3. 加载提示轮换

加载页状态文字每约 2.4 秒按顺序轮换：

1. 调用方传入的当前加载标题；
2. `正在准备球员与球场`；
3. `观众正在入场`；
4. `加载仍在进行，请稍后`。

规则：

- 仅在 `screen === "loading"` 且加载组件仍存在时轮换；
- 新一次加载重置为第一条；
- 进入首页、比赛、结果页或错误页后自动停止；
- 提示不改变真实进度，不把错误伪装成继续加载；
- 好友房间专用状态页继续使用自己的房间文案，不参与本轮轮换。

## 错误处理

- `takeControl` 抛错：记录一次告警并在下一帧重试，不中断物理主循环；
- scorer ID 越界、缺失或名单映射失败：使用得分方队长头像；
- 图片加载失败：沿用现有头像回退，不影响比分和庆祝；
- 页面已离开加载状态：提示轮换不再写入已销毁的文本对象。

## 测试与验收

### 自动测试

1. 活球状态下 `team` 存在但 `player` 为空时必须重新认领；
2. 已拥有有效球员时不得每帧重复 `takeControl`；
3. 手动切人和自动切人原有断言继续通过；
4. 红方0–6、蓝方7–13均映射到正确的14人头像；
5. 乌龙球头像取实际触球人，彩带取得分方；
6. 无效 scorer ID 回退队长；
7. 加载提示按顺序循环，离开加载页停止；
8. `npm run release:check` 全部通过。

### 开发者工具验收

- 上半场连续传球，至少让三名不同主队球员接球，均可立即移动、传球和射门；
- 手动切换到无球队员后，不被每帧强制抢回；
- 进入下半场后控制逻辑保持一致；
- 不同球员分别进球时弹出不同头像；
- 加载超过 7 秒时能看到至少三条不同提示，进入比赛后不再变化。

## 非范围与停止条件

不改变球员能力、AI难度、比赛规则、观众素材、广告配置或线上服务。本轮完成条件为专项测试、完整发布门禁和微信开发者工具比赛流程通过；上传新版本需在代码提交和推送完成后执行，提交审核仍由用户另行授权。

## 已确认的同轮产品增补

用户在实现过程中进一步明确以下项目，作为本轮验收范围：

- 赛前弹窗改为左侧“操作教学”、右侧“选择阵型”；教学面板加宽，左右手内容拉开，摇杆和动作键整体上移；
- 教学底部用常驻脚印说明传球接应方向，并用与实战一致的足球图标说明“长按射球，可以调整力度和方向”；
- 默认难度为“简单”，默认时长为“短”；
- 裁判球衣正背“裁判”二字放大到与球员队名相近的可读尺度；
- 分享按钮移到比分牌旁、位于暂停按钮之前并与暂停同尺寸；分享时自动暂停比赛和环境音，返回游戏后恢复分享前状态；好友客机无权冻结房主，仅暂停本机声音；
- 比分牌白底使用与暂停键相同的 `0.94` 不透明度；展开数据面板及场边队名牌底板继续使用 `0.72`，所有队名、比分、时间、控球率和牌面地名字保持 `alpha=1`；
- 分享按钮与暂停按钮统一为绿色、`0.94` 不透明度和相同尺寸；
- 分享标题使用当前权威比分和本地地域队名，例如“信宜镇隆天后街 VS 信宜镇隆金童 4:1！快来踢球”；
- 角球、界外球重开动作期间，控制权适配层必须尊重原引擎 `transitionToHuman` 资格判断，禁止自动切人取消 `Lob` / `Pass` / `ThrowInThrow`；动作完成后恢复正常自动切人。
