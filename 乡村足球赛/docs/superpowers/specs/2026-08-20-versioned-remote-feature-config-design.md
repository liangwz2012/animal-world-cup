# 乡村足球赛：版本化白名单云端配置设计

> 日期：2026-08-20  
> 状态：已确认设计，等待实施计划  
> 适用项目：微信小游戏 2D 首发候选版

## 1. 目标

建立一套可安全运营、可回滚、可测试的云端配置协议，让已经随审核版本交付的功能可以按节奏开启，并允许调整活动、任务、榜单和运营参数。

本设计解决以下已发现问题：

- 远程配置缓存没有有效期，历史开启状态可能在断网后长期残留；
- 客户端、配置服务和测试可能出现字段不同步；
- `minClientVersion` 等字段虽可下发，但没有清晰的执行语义；
- 通用 `customModules` 容易被误用为绕过专用字段白名单的扩展入口；
- 自动测试可以验证 JSON 归一化，却没有完整覆盖过期缓存、版本不兼容和紧急关闭流程。

## 2. 范围

### 2.1 本里程碑包含

- 远程配置协议版本、配置修订号、签发时间和失效时间；
- 客户端版本兼容判断；
- 缓存有效期与失败关闭策略；
- 客户端和服务端共用语义的模块白名单；
- 公告、维护状态和数据化活动列表；
- 已内置模块的运营参数归一化；
- 本地缓存迁移、过期处理和旧配置兼容；
- 客户端、服务端、缓存和发布门禁测试；
- 运维样例与回滚说明。

### 2.2 本里程碑不包含

- 远程下载或执行 JavaScript、WASM、模板表达式或其他可执行代码；
- 通过配置生成审核版本中不存在的新页面、新控件或新付费流程；
- 实现天气、杯赛、图鉴、通行证等具体玩法；
- 部署腾讯云、修改线上 Nginx、数据库迁移或开启生产开关；
- 替代微信后台的类目、隐私、广告位和版本审核流程。

## 3. 平台与合规边界

云端配置只能控制客户端已经包含并经过审核的能力。允许下发：

- 布尔开关；
- 数量、概率、日期、标题和受限枚举；
- 已知活动类型的数据记录；
- HTTPS/WSS 服务地址；
- 公告和联网维护信息。

禁止下发：

- 脚本、表达式、组件树和任意函数名；
- 未经白名单约束的资源地址；
- 可改变支付、广告、隐私授权含义的未知参数；
- 审核版本中不存在的新玩法逻辑。

远程配置是运营控制面，不是代码热更新系统。任何新增客户端逻辑仍需重新构建、上传和按平台要求审核。

## 4. 配置契约

### 4.1 顶层结构

```json
{
  "schemaVersion": 3,
  "revision": 12,
  "issuedAt": 1787191200000,
  "expiresAt": 1787277600000,
  "minClientVersion": "1.0.2",
  "maxClientVersion": "",
  "teams": [],
  "features": {},
  "announcement": {
    "text": "",
    "level": "info"
  },
  "maintenance": {
    "onlineBlocked": false,
    "message": ""
  },
  "events": []
}
```

字段语义：

| 字段 | 语义 |
| --- | --- |
| `schemaVersion` | 协议版本。客户端只接受明确支持的版本。 |
| `revision` | 单调递增配置修订号。低于本地已接受修订号的配置不得覆盖新缓存。 |
| `issuedAt` | 服务端配置签发时间，毫秒时间戳。 |
| `expiresAt` | 配置失效时间，必须晚于 `issuedAt`，最长有效期不超过 24 小时。 |
| `minClientVersion` | 允许应用该配置的最低客户端版本。 |
| `maxClientVersion` | 可选的最高客户端版本，用于停止向旧协议之外的版本投放。 |
| `teams` | 已存在队伍的受限覆盖数据，不创建任意新代码资源。 |
| `features` | 已知模块的开关和专用参数。 |
| `announcement` | 最多 100 字的公告及固定等级。 |
| `maintenance` | 联网能力紧急关闭信息，不得阻断离线单机。 |
| `events` | 已知活动类型的数据记录，不包含可执行内容。 |

### 4.2 功能模块白名单

保留专用字段：

- `leaderboard`
- `friend`
- `monetization`
- `dailyTasks`
- `penaltyShootout`
- `regionHonorBoard`
- `regionRivalry`
- `playerCodex`
- `spectateCheer`
- `challengeCard`
- `home`
- `weather`
- `tournament`
- `seasonPass`
- `achievements`
- `highlights`
- `dialectPack`
- `feedback`
- `experiments`

`customModules` 不作为生产开启新玩法的入口。兼容读取历史配置时可以保留并归一化，但所有条目必须强制为关闭，且不得被客户端业务模块消费。新增玩法必须先增加专用字段、参数白名单、客户端实现和测试，再随审核版本发布。

### 4.3 参数约束

沿用已有长度、数量、URL 协议和枚举限制，并增加以下公共规则：

- 数组必须限制最大条数；
- 文本必须去首尾空白并限制长度；
- URL 只接受 HTTPS/WSS，禁止凭据、查询令牌和本机地址；
- 时间范围必须满足 `startAt < endAt`；
- 未知字段全部丢弃；
- 缺失字段使用包内安全默认值；
- 模块只有在客户端实现状态为 `ready` 时才允许 `enabled=true`。

## 5. 客户端状态机

```text
包内默认配置（全部关闭）
  → 读取本地缓存
  → 校验协议、版本、修订号和有效期
  → 缓存有效：仅临时应用白名单配置
  → 后台请求远程配置
      ├─ 成功且更新：应用并原子写入缓存
      ├─ 成功但不兼容：保持安全默认或当前有效缓存
      └─ 失败：当前有效缓存可继续；过期缓存立即降级
```

### 5.1 缓存策略

- 缓存记录保存归一化后的配置、接收时间和最后成功修订号；
- 过期配置不得继续开启联网、广告、实验和未上线模块；
- 过期时允许保留不涉及联网、付费和权限的纯展示队伍覆盖，但必须使用单独的 `offlineSafe` 投影；
- 读取旧 v1/v2 缓存时执行一次迁移；无法可靠迁移时清除并回到包内默认；
- 写缓存使用完整对象单次替换，避免半写状态。

### 5.2 版本策略

- 客户端版本来自包内常量，不依赖远程数据自报；
- 低于 `minClientVersion` 或高于非空 `maxClientVersion` 时，不应用功能开关；
- 版本不兼容只关闭联网和远程模块，不阻断单机比赛；
- 可向用户展示非强制更新提示，但不能形成无法继续单机的强制墙。

### 5.3 维护策略

`maintenance.onlineBlocked=true` 时立即关闭：

- 排行榜读写；
- 好友房间；
- 在线活动提交；
- 广告和场次闸门；
- 依赖远程服务的助威、荣誉和赛季入口。

选队、AI 比赛、本地赛季和本地战绩继续可用。

## 6. 服务端行为

- `GET /v1` 返回归一化后的配置；
- 保持只读，不提供公网管理写接口；
- 配置文件超过 64 KiB、JSON 非法或字段非法时返回安全默认配置；
- 输出 `Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`；
- 服务端与客户端维护同一组字段语义和限制；
- `revision` 由运营修改时递增；
- `issuedAt`、`expiresAt` 在读取时验证，不自动信任文件内容；
- 日志只记录修订号、协议版本和错误类别，不记录用户标识或凭据。

## 7. 失败与回滚

| 场景 | 行为 |
| --- | --- |
| 配置服务 404/超时 | 使用尚未过期的缓存；无有效缓存则全部关闭。 |
| HTTPS/WSS 地址非法 | 对应模块关闭，其他模块继续。 |
| 配置修订号回退 | 拒绝覆盖新缓存并记录告警。 |
| 配置已过期 | 关闭联网、广告、实验和活动；保留单机。 |
| 客户端版本不兼容 | 不应用远程功能，展示可选更新提示。 |
| 配置 JSON 损坏 | 服务端下发安全默认，客户端也按无效处理。 |
| 线上玩法故障 | 运营发布更高修订号并关闭对应模块；必要时启用 `onlineBlocked`。 |

## 8. 测试与发布门禁

### 8.1 客户端测试

- 无缓存、无网络时全部关闭且单机可开赛；
- 有效缓存即时生效；
- 过期缓存关闭联网、广告和实验；
- 旧协议缓存安全迁移或清除；
- 远端修订号更低时不能覆盖；
- 客户端版本不兼容时不应用配置；
- 未知模块和未知参数被丢弃；
- `customModules` 无法开启任何业务模块；
- 维护状态关闭联网但不影响单机。

### 8.2 服务端测试

- 客户端和服务端对同一输入产生等价归一化结果；
- 配置文件损坏、超限和丢失时返回安全默认；
- 协议版本、修订号和时间窗口经过校验；
- 返回头和只读路由正确；
- 未知字段不下发。

### 8.3 发布门禁

- `npm run test:remote-config`
- `npm run test:remote-config-service`
- 新增缓存生命周期与客户端版本测试；
- `npm run release:check`
- 生产健康检查必须验证配置、排行榜和好友房三个真实入口；
- 微信开发者工具普通编译无阻塞弹窗；
- iOS、Android 各完成一次冷启动和完整单机对局。

## 9. 验收标准

1. 首发配置服务不可用时，单机无限畅玩且不出现联网、广告或实验入口。
2. 已过期的历史开启缓存不能继续开启任何联网或变现能力。
3. 客户端与服务端的白名单、默认值和钳制结果一致。
4. 低版本客户端不会应用面向新版本的配置。
5. 未知配置无法创建新玩法、执行代码或改变隐私/付费流程。
6. 配置回滚不需要重新部署客户端，但只能关闭或调整审核版本内置能力。
7. 完整发布门禁通过，并明确区分本地测试、服务部署和真机验收状态。

## 10. 实施停止条件

本里程碑在以下条件全部满足时结束：

- 协议、缓存、版本和服务端归一化实现完成；
- 专项测试和 `release:check` 通过；
- `STATUS.md` 更新真实状态；
- 不部署、不上传、不提审、不启用生产开关；
- 后续具体玩法作为独立里程碑另行设计和实现。
