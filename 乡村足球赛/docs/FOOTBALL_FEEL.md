# 《乡村足球赛》3D 足球动作与手感规格

> 版本：D0 / 2026-08-02
> 状态：研究与参数基线完成，尚未经真机手感实验验证
> 适用：M0 引擎试题、M1 贵州山地主场 5v5 纵向切片
> 原则：数字资产是原料，触球时序、球的独立运动和输入反馈才共同决定“有没有踢足球的感觉”。

## 1. 结论先行

不采用“买一包动作，播放时把球粘到脚上”的方案。最终路线是：

1. 一套不超过 65 骨的共享人形骨架 **humanoid-rural-v1**；
2. 一批经过“足球动作试镜”的跑动、停球、传球、射门、抢断和门将动作；
3. 每个动作带结构化的支撑脚、触球脚、触球帧和可修正距离元数据；
4. 模拟核在固定 30 Hz tick 上决定球的位置与冲量，动画只负责呈现；
5. 运行时使用方向融合、步幅匹配、轻量动作修正和两骨 IK，不在小游戏内跑扩散模型或全量 Motion Matching；
6. 用一个可实时拉参数、逐帧看触球的“手感实验室”完成调校，不靠开发者凭感觉改常量。

最终动作来源倾向于“专项低成本捕捉 + Blender 人工清理”。开放数据与商业包用于打样、补齐通用移动或做对照，不直接承诺为量产答案。

## 2. 为什么旧 2D 方案不能直接升维

旧比赛核的优点是规则闭环和输入已经存在，但动作层是一个通用 shoot 动作，传球、射门和挑传共用大量表现逻辑。旧核的踢球冲量在动作状态约 0.1333 s 时触发，但没有可供 3D 脚部对齐的触球点、支撑脚锁定和步幅资料。

因此：

- 可复用：规则状态、操作语义、比赛节奏、排行榜和地区/球队数据；
- 只作对照：移动、传射和地面阻尼数值；
- 必须重做：持球、连续触球、脚球接触、动画状态机、转身与急停、抢断、门将和球门碰撞表现。

### 2.1 旧数值快照

以下是在现有打包比赛核中已证实的值，单位和质量语义属于旧引擎，不把“力”解释为真实牛顿：

| 项目 | 旧值 | 3D 处理 |
| --- | ---: | --- |
| 球场 | 35 × 22.67 | 产品新基线是 64 × 42 m，不直接复用 |
| 球半径 | 0.12 | 改为法规尺寸附近的 0.11 m |
| 步行/跑动/冲刺 | 1.67 / 4.72 / 5.83 m/s | 作 legacy-normalized A/B 基线 |
| 持球移动 | 3.89 m/s | 保留“持球慢于跑动”的比例，重新校准 |
| 短传冲量 | 8–13 内部单位 | 保留轻/重传速层级，改用 m/s |
| 射门冲量 | 13–17.5 内部单位 | 只保留相对强弱，改用 m/s |
| 停球范围 | 0.4 | 改为脚、球、速度和压力共同决定 |
| 抢断时间 | 0.3 s | 拆为前摇、有效窗口和恢复三段 |

M1 手感实验室必须同时提供 **legacy-normalized**、**rural-balanced-v0** 和 **simulation-reference** 三套预设，用实际对比决定保留哪些节奏。

## 3. 骨架与角色绑定

### 3.1 humanoid-rural-v1

- 统一右手坐标、米制比例，引擎中 Y 轴向上；
- 标准 A-Pose，角色身高可变，骨架语义不变；
- 变形骨不超过 65，单顶点不超过 4 个权重；
- 必备：root、pelvis、腰/胸、颈/头、锁骨/上臂/前臂/手、大腿/小腿/脚/趾；
- 允许少量手臂和大腿 twist 骨，但不为手指建立全量骨架；
- 模型 root 是规则位置的视觉容器，模拟位置不由动画 root motion 回写；
- 绑定校验角色包含高、矮、瘦、壮四种体型，四种都要通过脚底和触球回归测试。

### 3.2 脚部语义点

不依赖网格顶点猜触球位置。每只脚定义以下语义点，可作为导出时的空节点或运行时局部偏移：

- **sole**：脚底支撑中心；
- **toe**：脚尖，用于步幅和挑球；
- **instep**：正脚背射门接触点；
- **inside**：脚内侧短传/推射接触点；
- **outside**：外脚背轻拨点。

语义点必须在网格换鞋、角色缩放和 LOD 切换后仍稳定。

### 3.3 动作坐标约定

- 源捕捉保留 60/120/240 FPS 原始档；
- 游戏导出档为 30 FPS，触球帧不得在采样后偏移超过半帧；
- 移动循环同时保留原始位移版用于分析，运行时使用 in-place 版；
- 所有脚球动作保留左/右脚语义，只有通过镜像校验的动作才可自动镜像；
- 每个 clip 单独导出，命名为 category_action_side_variant_vNN。

## 4. M1 动作覆盖

### 4.1 基础移动

- Idle 2 个变体；
- Walk / Jog / Sprint 前向循环；
- Jog 8 方向，或前/侧/后四方向加镜像；
- 0°/45°/90°/135°/180° 转向；
- 起步、急停、小跨步和倒退；
- 门将 Ready、Shuffle Left/Right、Forward Step。

### 4.2 足球接触

- 地滚球停球：左/右脚；
- 半高球卸球：脚内侧或大腿，M1 允许只有 1 组；
- 短传：左/右脚内侧；
- 大力地传：左/右；
- 长传/挑传：左/右；
- 正脚背射门：左/右；
- 脚内侧推射：左/右；
- 跑动中传球和射门各 1 组；
- 小触球拨球：内、外、前推；
- 正面抢断、侧面铲断、被撞踉跄；
- 头球 1 组；
- 门将低手接球、左/右侧扑、扑挡、手抛和大脚。

### 4.3 反应与情绪

- 轻微失衡、跌倒和起身；
- 进球庆祝 3 个变体；
- 赛后胜利、遗憾；
- 观众使用 6–10 个循环动作，不与球员动作包绑定。

M1 最小目标是 38 个经清理的原始 clip，再通过合法镜像、方向融合和速度参数扩展。不以“播放列表中有 150 个文件”代替触球质量。

## 5. 动作元数据与触球合同

每个触球 clip 必须有同名 JSON 元数据：

~~~json
{
  "id": "ball_short_pass_R_v01",
  "sourceFps": 60,
  "runtimeFps": 30,
  "durationMs": 633,
  "contact": {
    "timeMs": 166,
    "foot": "R",
    "socket": "inside",
    "expectedBallLocalM": [0.14, 0.11, 0.34],
    "maxVisualWarpM": 0.15
  },
  "plants": [
    { "foot": "L", "fromMs": 100, "toMs": 300, "maxDriftM": 0.06 }
  ],
  "entry": { "speedMin": 0, "speedMax": 3.5, "angleMaxDeg": 45 },
  "exit": { "recoverMs": 200 },
  "mirrorSafe": true,
  "licenseRef": "asset-ledger-id"
}
~~~

触球合同：

1. 按键输入在当前 tick 记录意图，并在 80 ms 内出现可见或可听反馈；
2. 模拟核根据动作类型预约一个触球 tick；
3. 表现层把 clip 的接触时间对齐到该 tick；
4. 在准备期只修正角色视觉 root 与腿部，不把球拉到脚下；
5. 到触球 tick 时，模拟核只施加一次冲量；
6. 超出动作的入场速度、角度或修正距离时，切换到更合适动作或失误动作，不强制对齐。

## 6. 运行时动画系统

### 6.1 移动

- 使用输入方向、规则速度和身体朝向驱动 2D blend tree；
- 动画步幅速度与模拟速度匹配，常规播放速率限制在 0.85–1.18；
- 超出范围时切换步态，不继续拉伸同一 clip；
- 支撑脚相位同步，急停和 90° 以上转向优先使用专用动作；
- 高画质对受控球员和球附近球员开脚底 IK，远处球员只用预清理动作。

### 6.2 持球与连续小触球

持球是规则上的“控球优先权”，不是节点父子关系。球始终是独立运动体。

- 每 140–220 ms 在可用脚和步态相位上安排一次小触球；
- 球的前置距离是 0.45–1.05 m，随速度、转向和技术属性变化；
- 急转时球靠近身体，冲刺时球更远；
- 对手进入压力区时降低引导强度，使抢断和停球失误真实发生；
- 球不穿脚、不围绕角色加速、不在换脚时瞬移。

### 6.3 动作修正与 IK

- 视觉 root 水平修正默认不超过 0.15 m，硬上限 0.18 m；
- 修正在 4–6 个渲染帧内完成，触球后平滑回收；
- 支撑脚的脚底滑动目标不超过 0.06 m；
- 触球点脚球距离 p95 不超过 0.08 m；
- IK 只修正髋、膝、踝和脚的小量误差，不拯救选错的动作；
- 超出限制时让球员踢偏、踢空或停大，不破坏球路。

## 7. 球的模拟与参数

### 7.1 真实锚点

现行规则的 5 号球周长为 68–70 cm，质量为 410–450 g，因此基线采用：

~~~text
radiusM = 0.11
massKg = 0.43
gravityMps2 = -9.81
airDensityKgM3 = 1.225
crossSectionM2 = PI * radiusM * radiusM
~~~

这些是尺度锚点，不意味着所有数值都追求专业 11v11 仿真。乡村小场、3 分钟赛制和触屏操作需要可读的游戏化调整。

### 7.3 空气阻力与弧线

实现采用小型可测模型，而不是引入整套刚体引擎：

~~~text
F_drag = -0.5 * rho * Cd * A * |v| * v
F_magnus = 0.5 * rho * Cl * A * |v|^2 * normalize(spin × v)
~~~

- Cd 可根据球速做两段近似，M1 先用单值；
- Cl 必须随旋转率限幅，不出现动画风格的急拐弯；
- 12 m 以内的普通短传不使用显著弧线；
- 排位模式所有地域球场共用同一规则地表参数，泥地、湿地和坑洼只做视觉差异，不制造地区公平性差异。

## 8. 传球、射门、停球和抢断

### 8.1 传球辅助

辅助只帮玩家选择合理意图，不保证结果。候选接球点依据以下项评分：

~~~text
score = directionFit * 0.38
      + distanceFit * 0.20
      + laneSafety * 0.22
      + receiverReadiness * 0.12
      + forwardValue * 0.08
~~~

- 易/普通/硬核锥角初始为 28° / 18° / 10°；
- 显示当前候选球员的脚下标记，让辅助结果可预期；
- 被防守者封堵时只会降分，不让球拐弯躲开对手；
- 手动定向传球跳过目标自动选择，但仍保留球员技术和压力散布。

### 8.2 射门

- 点按是脚内侧/普通射门，低前摇；
- 按住是正脚背蓄力，力量提升的同时转向灵活度降低；
- 射门散布由输入偏差、身体朝向、支撑脚稳定、压力和属性构成；
- 随机数只在可解释的散布内取样，不用“已命中/未命中”的隐藏投硬币；
- 触球、足球音效、轻微镜头反馈和球路必须在同一 tick 窗口对齐。

### 8.3 停球

- 根据球相对速度、来球高度、角度和防守压力选动作；
- 好停球是吸收约 70% 的相对速度并把球放在可继续操作的一侧；
- 失败不是球直接脱离控制，而是吸收率下降、停球距离变大、恢复时间增加；
- 输入缓冲允许玩家在球到脚前 120–200 ms 预输入下一次传球或射门。

### 8.4 抢断

- 站立抢断由面向角、脚球距离、双方速度和触球窗口决定；
- 背后进入时缩小有效窗口并增加踉跄/犯规风险；
- 铲球是高风险动作，M1 可与站立抢断共用按键但由距离和速度触发；
- 判定使用简化脚部扫掠体，不使用全身网格碰撞。

### 9.2 生产路线建议

1. **M0**：CMU 射门对照 + 一组可合法使用的通用移动，验证引擎导入、重定向、动画事件、IK 和包体；
2. **M1 动作试镜**：同时比较开放样本、1 个付费足球包试用/预览、1 组自捕动作；
3. **M1 量产**：邀请一名真正会踢球的业余或半专业球员，一次捕捉 25–35 个关键动作；
4. 用 Blender 完成去噪、脚底锁定、触球帧标注、重定向和左右变体；
5. 通用移动、观众和庆祝可用通过试镜的商业包补齐；
6. 购买、注册付费服务或向外部人员录制前，单独完成费用、肖像/动作授权和数据处理确认。

| 身体重心、摆腿和随动 | 15 | 显著“踢空气”感则淘汰 |
| 起步/恢复/与移动的衔接 | 15 | 必须能在可接受时间内返回可控状态 |
| 重定向到四种体型 | 10 | 膝/肘翻转或脚底系统性偏移则淘汰 |
| 覆盖、许可、包体和可编辑性 | 10 | 不允许商业游戏使用或不能存档授权证据则淘汰 |

任何“动作数量很多”但硬门失败的资产都不进生产包。

## 10. 手感实验室

M1 不先做整场比赛，先建立一个可自动验证的小场：一名受控球员、一名接球者、一名防守者、一名门将、球门、墙和米制网格。

### 10.1 必备工具

- 参数分组滑杆、数字输入和预设切换；
- 慢放、暂停、单 tick 和单渲染帧步进；
- 脚部语义点、支撑脚区间、模拟球位置和渲染球位置可视化；
- 预测球路、实际球路和历史轨迹叠加；
- 输入时间、动作起始、触球 tick、音效时间和触球误差时间线；
- 连续执行 100 次并输出 p50/p95/最大值；
- 将参数保存为带版本 JSON，可恢复、可 diff、可绑定重放证据。

### 10.2 六个基准练习

1. **静止停球 → 8 m 短传**：验证输入缓冲、停球和脚内侧触球；
2. **45° 慢跑中传球**：验证步态相位、转身和运动中误差；
3. **冲刺 → 急停 → 射门**：验证惯性、支撑脚和射门恢复；
4. **二过一**：验证传球选人、接球人预判和二次输入；
5. **正面抢断 → 恢复**：验证有效窗口、球的脱离方向和惩罚；
6. **12 m 射门 → 门将侧扑**：验证球路可预测、门将起跳和手球接触。

## 11. 验收门槛

### 11.1 机器指标

- 触球脚语义点与球面最近距离 p95 ≤ 0.08 m；
- 关键支撑段脚底水平漂移 p95 ≤ 0.06 m；
- 规则球位置与渲染球位置差 p95 ≤ 0.05 m，可见瞬移次数为 0；
- 移动输入到可见响应 p95 ≤ 100 ms；
- 传/射按键到按键、姿态或音效的输入确认 p95 ≤ 80 ms；
- 同一种子、同一输入和同一参数预设的模拟状态摘要 100% 一致；
- 手感实验室连续 10 分钟无 NaN、无球卡地、无动作状态死锁。

### 11.2 人工盲测

至少 5 名体验者不看参数名，交叉体验三套预设。通过条件：

- 至少 4/5 认为短传、停球和射门“像踢到球，而不是播放了动作”；
- 至少 4/5 能在三次尝试内完成停球后短传、运动中传球和冲刺后射门；
- 没有体验者高频报告“球被粘着”“脚没踢到球”或“按了没反应”；
- 记录完成时间、失败原因和主观评分，不只保留口头结论。

## 12. M0 与 M1 执行顺序

### M0 引擎门

同一个骨架、Idle/Run/Turn/Trap/Pass/Shoot 六类动作和同一个球，同时进入 LayaAir 与 Galacean，验证：

- GLB/动作导入、压缩和分包；
- 动画事件是否能稳定对齐 30 Hz 触球 tick；
- 四种体型重定向；
- 受控球员两骨 IK 的 CPU 成本；
- 微信开发者工具与 iOS/Android 真机稳定性。

M0 只决定引擎，不在两个引擎中各做一套正式动画系统。

### M1 手感门

1. 完成动作试镜；
2. 完成手感实验室六个练习；
3. 上述机器指标和盲测通过；
4. 才将同一组动作和参数放入 5v5 整局；
5. 手感门未过前，不量产省市场景、人物和球衣。
