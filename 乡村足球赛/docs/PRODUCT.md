# 《乡村足球赛》3D 升级产品需求文档

> 文档版本：1.0
> 日期：2026-08-02
> 产品状态：设计完成，等待 M0 技术闸门
> 首发平台：微信小游戏
> 工作名称：乡村足球赛；正式名称、商标与活动授权在发布前单独审查

## 1. 产品定义

《乡村足球赛》是一款以中国乡村群众足球为题材的 3D 微信小游戏。玩家选择省、市、区县、乡镇，并填写自己的村名或球队名，穿上具有当地色彩与纹样的球衣，在具有地域环境特征的乡村主场进行轻量 5v5/7v7 足球比赛，代表家乡争夺村、县、市、省和全国排行。

产品采用已确认的 **B 视觉方向**：

- 场景以真实中国乡村空间为依据，呈现可信的山地、田野、水乡、院落、看台、集市和村民观众；
- 球员采用原创动画电影式 3D 造型，比例亲切、表情清楚、动作有弹性；
- 不做廉价方块低模，也不追求主机级写实或电影离线渲染；目标是微信中高端机可稳定运行的“移动端精品 3D”。

“村超”是题材和氛围参照，不宣称获得任何现实赛事官方授权，不复制赛事标志、真实球队徽章、真实人物脸部或受保护转播包装。

## 2. 用户问题

现有 2D 版本已经具备地区、球队、球衣、比赛与排行的产品骨架，但存在四个主要问题：

1. 场景层次和动作有限，玩家难以感到“真的回到家乡球场”。
2. 各省文化主要停留在文字或颜色，缺少可见的建筑、地貌、观众和比赛氛围。
3. 角色动作和镜头缺少冲刺、停球、射门、对抗和庆祝的表演性。
4. 全国内容量巨大，如果为每个村制作独立重型地图，会超出微信包体、制作成本和维护能力。

## 3. 目标用户

### 3.1 核心用户

- 喜欢足球、村超、业余联赛和轻竞技的微信用户；
- 对家乡、省市身份和地区排行有参与感的用户；
- 需要 3–6 分钟一局、单手也能完成主要操作的轻度玩家；
- 愿意把球队卡片、赛果和排行分享给同乡或朋友的用户。

### 3.2 次要用户

- 不熟悉复杂足球游戏，但喜欢可爱 3D 人物与地方文化的用户；
- 通过朋友邀请进入房间，只玩少量对局的社交用户；
- 观战、收集球衣、经营家乡荣誉的非强操作用户。

## 4. 产品目标与非目标

### 4.1 产品目标

1. 在微信小游戏约束下做出一眼不是 2D 换皮的完整 3D 比赛体验。
2. 让玩家能自然表达“我来自哪里、代表哪支村队”。
3. 用共享地域家族 + 省级轻量叠加的方式覆盖 34 个省级地区，并可逐步追加精品市县包。
4. 保留现有快速比赛、赛季、挑战、排行和好友竞争的核心价值。
5. 首次进入即使断网或地域包失败，也能在通用球场完成一整局。
6. 从立项开始把包体、性能、文化准确性和真机验收作为功能完成的一部分。

### 4.2 本轮明确不做

- 不为全国每一个行政村建立真实坐标 3D 复刻；
- 不在首个纵向切片生产 34 省全部美术；
- 不做 11v11、复杂裁判规则、越位、球员转会和深度俱乐部经营；
- 不做主机级开放世界、室内探索、实时天气模拟或全动态昼夜；
- 不在客户端运行大型语言模型、图像模型或神经网络足球 AI；
- 不在 M1 接入付费、广告、全球排行或好友实时联机；
- 不把第三方实景瓦片、真实赛事视频或未授权照片打包进游戏。

## 5. 产品原则

### 5.1 先有一块精品，再有全国数量

M1 只完成一块“贵州西南山地村场”及一套 5v5 球员。只有该切片通过视觉、玩法、真机和包体四项验收，才开始扩展九个地域家族和 34 省叠加层。

### 5.2 地域身份真实，但不制造刻板印象

地域差异来自地貌、常见建造材料、气候色彩、农业景观、地方纹样和观赛方式，不用夸张口音、奇装异服或单一民族符号代表整个省份。

### 5.3 普通人就是主角

球员原型来自乡村教师、司机、摊主、工友、返乡青年、学生、种植户等普通人。年龄、体型、肤色和面部轮廓有自然差异，但不复制真实人物，不把职业做成戏谑标签。

### 5.4 完成意味着真实证据通过

网页能跑、编辑器无报错、截图好看都不等于功能完成。与运行相关的里程碑必须在微信开发者工具、iOS 真机和 Android 真机分别留下证据。

## 6. 核心体验循环

```text
选择/确认家乡
  → 创建村队和球衣
  → 选择比赛模式
  → 下载或复用地域主场包
  → 3D 比赛
  → 赛果、评分和地域积分
  → 查看排行/分享/再来一局
```

首局目标：新用户从进入游戏到开球不超过 90 秒，其中填写村名可以跳过并使用系统安全名称。

## 7. 地区与球队系统

### 7.1 地区层级

沿用现有数据与流程：

```text
省级地区
  → 地级市/自治州/地区
  → 区/县/县级市
  → 乡/镇/街道
  → 玩家自填村名或社区球队名
```

- 行政区数据来自项目已维护的版本化清单；
- 不虚构“全国所有村”的数据库；
- 村名是玩家自定义文本，经过长度、敏感词、冒充官方和重复空白检查；
- 玩家选择地区不调用 GPS，不读取实时定位；
- 港澳台地区按产品现有省级地区结构处理，展示名称与地图数据发布前统一合规复核。

### 7.2 球队身份

每支球队包含：

- `teamId`：服务端生成；
- 地区路径：省/市/县/乡镇代码；
- 显示名称：2–10 个中文字符或合规中英文组合；
- 队徽：模板形状 + 地域纹样 + 颜色，不允许上传任意图片；
- 主客场球衣：模板、主色、辅色、号码和短队名；
- 主场包：地域家族 + 省级叠加 + 可选精品市县包；
- 成绩：本地记录或服务端赛季记录，二者状态明确区分。

### 7.3 地域内容分级

| 级别 | 覆盖方式 | 主要内容 | 包体策略 |
| --- | --- | --- | --- |
| L0 通用 | 所有人本地可用 | 标准乡村球场、通用远景、通用观众 | 首发本地资源包 |
| L1 地域家族 | 9 个家族 | 核心地貌、建筑套件、植被、边线道具、天空色 | 首个本地，其余远程按需 |
| L2 省级叠加 | 34 个省级地区 | 配色、纹样、标牌、植被组合、远景轮廓、观众配置 | 轻量数据和小纹理远程包 |
| L3 精品市县 | 持续追加 | 经过考证的地标、主场入口、特色看台或街巷 | 独立远程内容包 |
| L4 合作村队 | 授权项目 | 真实队名、队徽、球员或赛事元素 | 单独授权与审核，不进入默认范围 |

## 8. 3D 比赛玩法

### 8.1 阵容与场地

- M1：5v5，包括门将；
- 正式基础模式：7v7，包括门将；
- 比赛时长：默认 3 分钟净时间，活动配置可为 2–5 分钟；
- 球场基础尺寸：64×42 米的游戏化小场，边界和禁区按可读性调整；
- 不实现越位；界外球、角球和球门球使用 1–2 秒快速重开；
- 平局在普通模式直接结算，淘汰赛进入三轮点球。

### 8.2 操作

左侧：虚拟摇杆移动。右侧采用四个上下文按钮：

- **传球**：点按地面短传；按住拖向队友进行定向传球；无球队员时切换/呼叫；
- **射门**：点按普通射门；按住蓄力并控制方向；禁区外自动提高弧线容错；
- **冲刺/抢断**：持球时冲刺，无球接近对手时抢断；有体力和短冷却；
- **挑传/切换**：持球时挑传，无球时切换到推荐防守球员。

控制目标是“容易完成正确意图”，不是复刻手柄足球的全部组合键。所有关键动作都提供按键高亮、方向线或目标圈反馈。

### 8.3 足球规则与手感

- 比赛模拟固定 30 Hz，渲染可为 30/45/60 FPS；
- 球使用轻量球体运动、滚动阻尼、弹跳、门柱碰撞和网内阻尼；
- 球员使用胶囊体与场地边界，不引入完整刚体物理运行时；
- 传球方向受输入、球员朝向、距离、压力和属性轻度影响；
- 射门使用可预测的目标散布，不用完全随机失败；
- 抢断有前摇、有效角度和恢复时间，背后抢断成功率显著降低；
- 门将采用状态机和预判区域，不读取未来球轨迹作弊；
- AI 只读取规则允许的信息，不使用大型模型运行时。

### 8.4 镜头

- 默认为横屏 3/4 转播镜头，俯角约 32–38°；
- 镜头根据球与受控球员形成的兴趣点平滑移动；
- 进攻进入禁区时轻微推近，长传时扩大视野；
- 射门、扑救和进球只使用 0.3–0.8 秒轻量强调，不打断操作；
- 低画质不减少可见比赛信息，只降低阴影、观众和远景细节。

## 9. 角色与阵容

### 9.1 角色系统

首批建立 12–14 个普通人职业/生活原型，通过模块组合形成更多外观：

- 共享一套 65 骨以内的人形骨架；
- 头型、发型、眉眼、体型、肤色、年龄细节和球衣可组合；
- 角色比例为 6–6.5 头身，手脚略大以增强手机屏幕动作可读性；
- 不用职业制服上场，职业只体现在人物档案、体态和生活故事；
- 男、女角色均可参与同一球队，不做性能或能力刻板差异。

### 9.2 动作清单

M1 必备：Idle、Walk、Run、Sprint、Turn、Trap、ShortPass、LongPass、Shoot、Tackle、Stumble、KeeperReady、KeeperDive、Celebrate、Defeat。

动作允许左右镜像和上半身叠加，但所有角色必须使用同一命名与根运动约定。比赛位移由模拟驱动，动画根运动不得直接决定规则位置。

上述是产品动作类别，不是资产文件数量。骨架、左右脚变体、最低 38 个原始 clip、触球元数据、参数和手感门以 FOOTBALL_FEEL.md 为准。

## 10. 地域场景系统

沿用现有九个地域家族：

1. 京津沪现代乡郊；
2. 北方平原麦场；
3. 东北黑土村场；
4. 江南水乡村场；
5. 岭南乡村球场；
6. 西南山地村场；
7. 西北乡村球场；
8. 高原乡村球场；
9. 海岛沿海村场。

每个家族共享球场外围地形、建筑套件、植被、看台和天空语言；省级叠加层改变颜色、纹样、标牌、道具组合和远景轮廓。城市/县/村身份主要由球队名称、旗帜、计分牌、入场字幕和少量特色锚点表达，不复制一整套重型几何。

## 11. 比赛模式

| 模式 | 玩法 | 首次交付 |
| --- | --- | --- |
| 快速比赛 | 选择对手强度，立即进行单局 | M1 |
| 每日挑战 | 固定阵容、天气色调或落后追分条件 | M4 |
| 乡村赛季 | 小组赛 + 淘汰赛，积累本地奖杯 | M4 |
| 地域排位 | 按赛季积分进入村/县/市/省/全国榜 | M5，需真实服务 |
| 好友约战 | 分享房间卡片，实时或异步挑战 | M5，需真实服务 |
| 观战 | 观看好友/高排名对局摘要或实时房间 | M5 后评估 |
| 点球大战 | 快速独立玩法，也用于淘汰赛决胜 | M4 |

## 12. 排行榜

### 12.1 排行维度

- 全国；
- 省级地区；
- 市/州；
- 区/县；
- 乡镇；
- 自定义村队；
- 好友；
- 赛季、周榜和历史荣誉。

### 12.2 积分与公平

- 单机 M1 只有明确标注的“本机记录”，不得伪装成全国实时排行；
- M5 服务端权威计算积分、对手强度、连胜修正和异常对局；
- 断线补偿、重复对手、刷分设备和异常时长进入风控；
- 地区由玩家主动选择，排行页明确“代表地区”，不暗示 GPS 真实性；
- 用户名、村名、队徽和分享文案均经过内容安全处理。

## 13. 新手、失败与恢复

### 13.1 首次体验

1. 默认使用上次地区；新用户先选择省级地区，可稍后补完详细地址。
2. 系统提供安全默认队名和球衣，所有自定义均可跳过。
3. 只下载首场所需资源；显示真实大小、进度和预计状态。
4. 30 秒交互教程覆盖移动、传球、射门和抢断。
5. 首局 AI 难度根据操作表现动态降低，但不篡改射门结果。

### 13.2 可恢复异常

- 地域包失败：校验一次、重试一次，随后切换本地通用球场；
- 贴图或角色 LOD 缺失：使用同骨架基础角色和默认材质；
- 内存压力：立即降低 DPR、阴影、观众和远景，不中断比赛；
- 切后台：暂停单机模拟，恢复后 3 秒倒计时继续；
- 排行服务不可用：赛果进入签名本地队列，页面标记“待同步”；
- 好友房断线：宽限期重连，超过期限由 AI 接管；
- 内容被拦截：使用安全默认队名，不丢失其他球队配置。

## 14. 成功指标

### 14.1 M1 产品验收指标

- 80% 以上目标用户在无文字提示的定向问卷中识别出“西南山地/贵州乡村足球”氛围；
- 80% 以上测试用户能在 60 秒内独立完成移动、传球和射门；
- 70% 以上首次开球用户完成整局；
- 一局内因镜头遮挡、误切球员或按钮误触造成的明确投诉每人不超过 1 次；
- 角色、球衣和场景没有被测试者描述为“方块占位”“纸片人”或“2D 套 3D 壳”。

### 14.2 上线观察目标

这些是上线后的产品假设，不作为本地实现完成声明：

- 首局完成率 ≥ 70%；
- 首局后再开一局比例 ≥ 35%；
- 崩溃自由会话 ≥ 99.5%；
- 地域包下载失败率 < 2%，失败后的本地兜底成功率 ≥ 99%；
- 分享进入后完成一局比例 ≥ 30%；
- 有效对局中的平均局长为 3–6 分钟。

## 15. 商业化边界

M0–M4 不接入支付和广告。未来如商业化，只考虑不影响数值公平的球衣、入场动作、庆祝动作、主场装饰和赛季纪念内容；真实队伍或赛事联名必须先有书面授权。任何付费方案需另行产品、合规和未成年人保护评审。
