# 《乡村足球赛》3D 验收总则

> 版本：2026-08-02
> 用途：定义什么证据能证明设计、实现、接入、部署和发布真正完成。

## 1. 状态分级

所有功能必须使用以下状态之一，不得合并表述：

| 状态 | 含义 |
| --- | --- |
| 设计完成 | 产品、交互、视觉、架构和验收文档已收敛 |
| 本地实现完成 | 代码与本地资源已完成，自动测试通过 |
| 开发者工具通过 | 微信开发者工具中的目标路径通过 |
| 真机通过 | 指定 iOS/Android 设备和版本有证据 |
| 测试服务接入 | 真实测试服务可用，不等于生产服务 |
| 生产服务接入 | 生产配置与凭证已接入，不等于已部署 |
| 部署完成 | 目标环境真实可访问 |
| 审核通过 | 微信平台审核真实通过 |
| 灰度完成 | 真实灰度用户可使用且指标正常 |
| 全量发布 | 已对目标用户全量开放 |

## 2. 证据规则

每项验收证据至少记录：

- 里程碑、构建号、Git 提交；
- 引擎、依赖锁文件、资源清单版本；
- 设备型号、系统、微信版本和画质档；
- 测试开始/结束时间与持续时长；
- 自动输入或人工路径；
- 原始日志、截图/录像、性能与包体文件路径；
- 通过、失败、跳过和跳过原因；
- 执行人或自动化任务标识。

截图不能代替交互测试，编辑器预览不能代替真机，单次平均 FPS 不能代替帧时间分布。

## 3. D0 设计验收

- PRODUCT.md 明确目标、非目标、首个 5v5 切片和全国扩展边界；
- USER_FLOWS.md 覆盖首次进入、地区选队、资源失败、比赛、结算和排行；
- DESIGN_SYSTEM.md 定义 B 方向、角色/场景预算、地域家族和六张金图；
- ARCHITECTURE.md 定义纯 TypeScript 模拟核、RenderPort、资源清单和微信包策略；
- ASSET_PIPELINE.md 定义 Blender 确定性管线、隔离区、许可账本与模型预算；
- FOOTBALL_FEEL.md 定义骨架、动作试镜、触球合同、参数与手感门；
- RESEARCH_3D_STACK.md 的引擎结论与 DEVELOPMENT.md/MILESTONES.md 一致；
- LESSONS_HIDE_AND_SEEK.md 的结论来自本机证据，不推断未知模型；
- STATUS.md 如实写明尚未创建 3D 正式实现；
- 设计文档没有相互矛盾的首发阵容、场地、包体或引擎结论。

## 4. M0 引擎验收

### 4.1 同题公平

- 两候选读取同一模拟帧；
- 使用同一模型、骨架、动作、纹理、场景代理和音频；
- 使用同一测试输入、时长、镜头和画质；
- 不为某候选单独删功能或降低画质；
- 所有人工编辑器步骤均记录并尽量转成版本化配置。

### 4.2 微信平台

- 冷启动进入 M0 场；
- 双指移动 + 动作不互相吞触摸；
- 前后台 10 次不丢失渲染或输入；
- 网络关闭、超时、404、哈希错误均进入明确回退；
- 本地分包只有自包含模块，遵守项目 AGENTS.md；
- 缓存损坏可删除单包并重新下载；
- 低内存告警后能降级或安全退出比赛；
- 开发者工具、iOS 真机、Android 真机分别记录。

### 4.3 性能与包体

- 主包内部目标 ≤ 3.4 MiB，硬门 ≤ 4 MiB；
- 本地总包内部目标 ≤ 18 MiB，硬门 ≤ 20 MiB；
- 中档机目标 30 FPS；
- 报告 p50、p95、p99 帧时间，不只报告平均 FPS；
- 10 分钟后帧时间和内存不持续恶化；
- 记录 Draw Call、三角面、骨骼角色数、纹理内存估算；
- 远程资源不包含可执行 JS/WASM。

### 4.4 可维护性

- 干净安装可构建；
- 关闭 IDE/MCP/AI 后可构建；
- 构建不依赖未提交的全局路径或用户偏好；
- RenderPort 外没有引擎对象泄漏进 MatchCore；
- 失败日志能定位资源、平台、引擎或业务层；
- 两次同类修复后仍失败则记录为硬风险，不无限打补丁。

## 5. M1-A 足球手感验收

以 FOOTBALL_FEEL.md 为唯一详细手感标准。最低硬门：

- 触球脚到球面误差 p95 ≤ 8 cm；
- 支撑脚滑动 p95 ≤ 6 cm；
- 规则球与渲染球误差 p95 ≤ 5 cm；
- 可见球瞬移为 0；
- 移动输入可见响应 p95 ≤ 100 ms；
- 动作输入确认 p95 ≤ 80 ms；
- 同输入重放状态摘要 100% 一致；
- 六个练习连续 100 次没有 NaN、死锁、球卡地；
- 四种体型重定向通过；
- 5 人盲测至少 4 人认可停、传、射的触球感；
- 动作资产许可账本完整。

以下任一项直接失败：

- 持球时把球作为脚或人物节点子对象；
- 动画事件直接改变比分、规则位置或控球权；
- 用超过 18 cm 的角色修正掩盖选错动作；
- 用球瞬移追脚；
- 非商业、来源不明或仅研究许可的动作进入产品包；
- 为追求华丽动作牺牲按键响应或规则确定性。

## 6. M1-B 产品纵向切片验收

### 6.1 功能

- 首次用户能选择/使用默认本地队；
- 赛前显示双方地区、队名、球衣和阵容；
- 完整进行开球、三分钟比赛、结算；
- 移动、传球、挑传、射门、冲刺/抢断、切人均可用；
- 进球、出界、角球、球门球和界外球能快速重开；
- 暂停、前后台和意外中断有明确恢复；
- 无网络时可用通用场完成单机。

### 6.2 视觉

- 六张固定金图全部通过；
- 第一眼是暖色、可信、有人情味的 3D 乡村群众足球；
- 角色不是二维纸片、默认胶囊或商店原样模型；
- 6–6.5 头身、手脚略大，但身体受力可信；
- 球衣、场边、建筑、植被和人群层次达到 DESIGN_SYSTEM.md；
- 手机实际画面能分清球、受控球员、队友、对手、球门和操作反馈；
- 地域文化来自组合，不靠刻板化单一符号。

### 6.3 性能

- iOS/Android 中档机均完成 10 分钟；
- 中档 30 FPS 目标通过，低档安全模式可完成比赛；
- 画质降级不移除球、边线、球门、队伍识别和操作提示；
- 场景切换后比赛资源可释放；
- 连续三局没有显著内存爬升；
- 下载时不阻塞 UI，断网不进入黑屏。

### 6.4 用户体验

- 5 名首次用户中至少 4 名三次内完成移动、传球和射门；
- 至少 4 名能说出当前代表的地区/球队；
- 至少 4 名认为画面不是“占位原型”；
- 没有高频误触、按钮遮挡、目标选择不可理解；
- 失败提示能说清发生了什么以及如何继续。

## 7. 地域内容验收

- 每个资产有来源、作者/工具、提示词或采购单、许可、哈希；
- AI 生成内容经过人工结构、透视、文字和文化审核；
- 不使用真实村超、足协、俱乐部、学校、赞助商标志，除非有书面授权；
- 真实人物肖像、动作捕捉和声音有对应授权；
- 省级元素由当地可解释资料支持；
- 同一地域不把单一民族服饰、食物或地标当成全部身份；
- 市县村默认用数据组合，不承诺逐村建模；
- 排位中的物理与属性不因地域皮肤改变；
- 资源包有版本、哈希、大小、依赖和回退。

## 8. 在线与数据验收

- 客户端不直接决定排名分数；
- 赛局有唯一 ID、种子、构建版本和状态摘要；
- 重复提交幂等；
- 离线队列可重试且不会重复计分；
- 昵称、头像、地区授权与用途有清楚提示；
- 不收集比赛不需要的精确位置或通讯录；
- 远程配置采用白名单字段、签名/完整性和版本控制；
- 服务端不可用不破坏本地存档；
- 测试环境与生产环境严格区分；
- 未完成生产部署时 UI 不显示虚假的全国实时数据。

## 9. 发布阻断项

出现以下任一项不得进入灰度：

- 主包或本地总包超过微信硬限制；
- 任一目标系统无法完成一整局；
- 冷启动黑屏、资源失败无回退、前后台后无法继续；
- 球频繁粘脚、瞬移、穿门柱或触球错位；
- 未授权商标、人像、动作、音乐或字体；
- 隐私说明与实际数据行为不一致；
- 排行可由客户端任意伪造；
- 灰度开关、回滚或严重问题关闭路径不可用；
- 状态文档与真实部署状态不一致。

## 10. 缺陷优先级

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 数据损坏、无法启动、支付/隐私/安全事故、广泛崩溃 | 立即阻断与回滚 |
| P1 | 无法完成比赛、主操作失效、严重球/动作错位、目标机持续掉帧 | 阻断里程碑 |
| P2 | 可恢复功能问题、明显视觉破绽、少数设备性能问题 | 修复后复验 |
| P3 | 轻微文案、低频装饰问题、非关键优化 | 记录排期 |

每个 P0/P1 修复必须新增自动测试、重放或真机回归步骤，不能只改代码后口头关闭。
