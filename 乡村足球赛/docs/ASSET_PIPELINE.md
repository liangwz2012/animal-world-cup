# 《乡村足球赛》3D 资产生产与验收管线

> 文档版本：1.0
> 日期：2026-08-02
> 主管线：Blender 5.1.2 + 版本化脚本 + GLB/压缩纹理
> 原则：AI 生成是候选输入，不是可直接发布的成品

## 1. 资产目标

资产管线同时解决五个问题：

1. B 方向的最终画面不能停留在方块草图；
2. 12–14 名角色和全国地域内容不能靠逐个手工复制；
3. 微信包体、纹理内存、骨骼和 Draw Call 必须在导出时受控；
4. 每个地域元素要有资料、许可和文化审核依据；
5. 即使更换 AI 模型或渲染引擎，Blender 源资产和审核结果仍可重建。

## 2. 目录与晋级状态

```text
next3d/assets-src/
  registry/                    来源、许可、文化与审核清单
  references/                  只作考证，不进入运行包
  concepts/                    原创概念图和三视图
  quarantine/                  AI/外部候选，默认不可发布
  characters/
    shared-rig/
    bodies/
    heads/
    hair/
    kits/
    animations/
  stadiums/
    generic/
    region-families/
    province-overlays/
    hero-locales/
  props/
  materials/
  audio/
  blender/
  export-presets/

next3d/assets-built/
  preview/                     网页/引擎预览产物
  wechat/                      已压缩运行资产
  manifests/                   构建生成清单与哈希
  reports/                     面数、材质、骨骼、贴图和许可报告
```

资产状态只有以下五种：

- `reference-only`：仅可查看；
- `quarantine`：来源或质量未审，禁止打包；
- `work-in-progress`：自有源资产，尚未通过全部门；
- `approved-preview`：可进入内部演示；
- `approved-release`：通过许可、文化、技术和视觉四门，可进入发布包。

构建脚本只接受 `approved-release`。

## 3. 来源登记

每个外部参考或生成物有一条不可省略的登记：

```yaml
asset_id: ref-guizhou-terrace-001
kind: photo-reference
source_url: https://example.invalid/record-only
accessed_at: 2026-08-02
author: recorded-owner
license: reference-only
allowed_use: visual-research
contains_person: false
contains_logo: false
ai_tool: none
review_state: reference-only
notes: not distributed with game
```

实际 URL、作者和许可必须来自真实资料，示例值不会进入登记库。缺少作者、许可或允许用途的内容只能 `reference-only`，不能当贴图、模型或训练素材。

### 3.1 资料优先级

1. 政府/地方公开且许可明确的文字与图片资料；
2. 地方志、博物馆、院校、权威建筑/农业资料；
3. 自行拍摄或书面授权素材；
4. OSM 等许可清楚的数据用于空间类型和道路骨架；
5. 普通网络图片只作人工考证，不下载进运行资产；
6. 地图实景瓦片、街景和无许可模型不做离线提取、描摹或分发。

## 4. 角色生产流程

```text
普通人角色设定
  → 原创正/侧/背概念
  → 共享比例网格
  → 头/发/体型模块
  → 干净拓扑与 UV
  → 共享骨架绑定
  → 表情与动作
  → 球衣遮罩/材质变体
  → LOD0/1/2
  → 烘焙/图集/压缩
  → GLB 导出
  → 引擎与真机验收
```

### 4.1 共享骨架

- 骨架 ID 固定为 `humanoid-rural-v1`；
- 骨骼总数不超过 65，单顶点最多 4 个影响；
- 根节点、髋、脊柱、颈、头、四肢、手脚和可选面部辅助骨命名版本化；
- 所有角色使用同一静止姿态、单位、朝向和脚底高度；
- 动画文件只存一份共享动作，不复制到每个角色 GLB；
- UniRig/AniGen 产生的绑定必须重映射到共享骨架并通过动作压力测试。

### 4.2 网格

- LOD0：8k–12k 三角面，首页/庆祝/近景；
- LOD1：4k–6k，正常比赛；
- LOD2：1k–1.8k，远端和低档；
- 轮廓优先保留头、肩、手、鞋和发型，衣服褶皱优先烘焙；
- 腋下、髋、膝、肘和脚踝做极限动作变形检查；
- 不允许重叠身体造成无意义面数，球衣覆盖区域可裁减内层；
- 面法线、切线、UV、材质槽和骨骼权重必须由工具检查。

### 4.3 材质和贴图

- 一个角色家族共享基础肤色/头发/球衣材质；
- 颜色变化走参数和遮罩，不复制整张纹理；
- 运行纹理从高分辨率源图烘焙生成，禁止直接手改压缩产物；
- 角色默认使用 1024 图集；低档可使用 512；
- 法线和 ORM 按引擎兼容方案合并；
- 中文号码/短队名由小型动态层生成，避免完整字体进入每个球衣贴图。

### 4.4 动作

动作源统一 30 FPS，关键触球帧写入旁车元数据：

```json
{
  "clip": "short_pass_r_v1",
  "durationFrames": 28,
  "contactFrame": 14,
  "recoverFrame": 22,
  "mirrorSafe": true,
  "rootMotion": "visual-only"
}
```

导出器校验动画名称、长度、触球帧、循环、根位移和足底滑动。触球事件不直接改规则状态，只供表现层对齐。

## 5. 场景生产流程

### 5.1 模块化层级

```text
通用球场核心
  + 地域家族地形/建筑/植被套件
  + 省级轻量配色/纹样/标牌/远景叠加
  + 可选精品市县英雄资产
  + 队名/旗帜/计分牌的运行时身份层
```

通用球场负责规则尺寸、球门、边线、替补席和碰撞；地域层不能改变比赛核心坐标。这样同一重放、AI 和网络状态可以在不同主场显示。

### 5.2 家族资产清单

每个地域家族至少包含：

- 一套 128 米内地形与远景轮廓；
- 6–10 个模块化建筑体块；
- 2 个近景看台/棚架组合；
- 8–12 个边线生活道具；
- 4–6 个植被网格和 2 套材质变化；
- 一套观众服装/道具色板；
- 一套天空、雾和主光配置；
- 一套碰撞代理、遮挡体和 LOD；
- 一份文化证据板和禁用元素清单。

### 5.3 场景预算

- 中档默认镜头可见三角面 ≤300k；
- 静态不透明 Draw Call 目标 ≤60，整帧目标 ≤100–120；
- 0–60 米资产有 LOD0/1，60 米外使用 LOD2 或合并远景；
- 重复观众、树木、旗杆、椅子和摊位优先 GPU 实例化；
- 单地域运行纹理常驻目标 ≤48 MiB，角色/球/UI 另计；
- 单一远程地域包目标 3–8 MiB；精品英雄包可单独下载，不阻塞通用比赛。

### 5.4 光照资产

- M1 只发布一套午后暖阳；
- 静态 AO/顶点 AO 在 Blender 烘焙；
- 若使用 lightmap，单家族限制为 1–2 张 1024/2048，按真机内存决定；
- 阴影代理与视觉网格分离；
- 高中低档引用同一资产语义，不能由三套手工场景漂移。

## 6. 球衣与队徽管线

### 6.1 球衣模板

- `kit-classic-panel`：经典侧片；
- `kit-river-wave`：水纹节奏；
- `kit-terrace-step`：梯田折线；
- `kit-brick-band`：砖带结构；
- `kit-field-stripe`：田垄条带；
- `kit-mountain-chevron`：山形折线；
- `kit-coastal-current`：沿海流线；
- `kit-plain-block`：平原大色块。

模板只是几何/遮罩语言；具体省份颜色和纹样经文化审核后组合。队徽使用 8–12 个基础轮廓和白名单图形，不允许玩家上传图片。

### 6.2 动态文字

- 允许字符、长度和禁用词由数据层验证；
- 号码和队名在离屏 Canvas 生成 256/512 小图；
- 纹理缓存键为字体版本 + 文字 + 颜色 + 尺寸；
- 同队共享一张号码/队名字形图集；
- 生成失败时使用号码和默认短队名，不影响比赛。

## 7. AI 工具使用

### 7.1 可用节点

- 概念探索：地域构图、人物轮廓、配色候选；
- 高模草稿：静态小道具、头部、建筑装饰；
- 绑定候选：非关键角色的初始骨骼/权重；
- 材质参考：砖、木、石、泥土和织物的高频细节；
- Blender 操作：批量命名、LOD、烘焙、检查和导出脚本编写。

### 7.2 禁止自动放行

- 可识别真实人物脸部；
- 民族、宗教或政治符号；
- 主角最终拓扑、共享骨架和碰撞体；
- 带文字的最终球衣；
- 未知许可证模型、纹理和动作；
- 百万面/4K AI 输出直接打包；
- 由 AI 自己声明“符合某省文化”而无外部证据。

### 7.3 安全

BlenderMCP 可执行本地 Python，只允许连接受信任的本地 Blender 会话。运行前保存源文件，禁止把仓库密钥、微信配置或用户数据暴露给 MCP。正式导出由审计过的命令行脚本执行，不依赖对话历史。

## 8. 命名与版本

命名格式：

```text
{domain}_{family}_{item}_{variant}_{lod}_{version}
chr_shared_body_a_lod0_v001
chr_hair_short_wavy_b_lod1_v003
ani_humanoid_short_pass_r_v002
env_sw_mountain_stand_wood_a_lod1_v004
prop_generic_goal_net_a_lod0_v002
mat_kit_terrace_mask_a_v001
```

- 文件名只用小写英文、数字和下划线；
- 显示中文放在数据表，不写入资源路径；
- 破坏骨架/UV/碰撞契约时升级主版本；
- 仅贴图或材质微调升级补丁版本；
- 运行清单引用内容哈希，不引用 `latest`。

## 9. 自动资产门

每次导出自动检查：

1. 文件扩展、命名和版本；
2. 三角面、顶点、材质槽和 Draw Call 估算；
3. 骨骼数量、影响数、缺权重和极小权重；
4. 尺寸、原点、朝向、负缩放和未应用变换；
5. UV 越界、重叠策略、法线和切线；
6. 贴图尺寸、通道、颜色空间、MIP 和压缩目标；
7. LOD 覆盖和屏幕误差；
8. 碰撞代理、出生区和比赛禁区；
9. 许可、文化、AI 来源和审核状态；
10. GLB 是否含相机、灯光、隐藏高模、未用动画或源图。

任一硬错误使构建失败，警告必须在报告中显式豁免并注明责任人和过期版本。

## 10. 视觉资产门

### 10.1 角色金模门

在批量生产角色前，一名球员必须同时通过：

- 中性棚拍正/侧/背；
- 面部近景；
- 主客场球衣；
- 跑、停、传、射、抢断和庆祝；
- LOD 切换无明显爆点；
- 中画质微信真机默认比赛镜头；
- 低画质不退化为折面/纸片；
- 许可和原创性审核。

未通过时只能迭代该金模，不新增第 2–14 名角色。

### 10.2 主场金角门

在扩建整座 M1 球场前，先做一个 25×25 米边线角落，包含草皮、围挡、看台、村民、摊位、近景建筑、树和远山。它必须在默认比赛镜头、低机位和低画质三种机位过审。该门直接防止程序化占位铺满全图后再返工。

## 11. 引擎交叉验证

M0 的 LayaAir 与 Galacean 不能各自使用不同导出资产。资产编译器生成一个中间清单和同一组 GLB/纹理；引擎端只做必要格式适配。若某引擎要求私有转换格式，必须证明可从同一 GLB 源自动生成，禁止在编辑器里维护第二份手工美术真源。

## 12. 发布资产门

发布前生成：

- 本地/远程包大小和哈希；
- 每包许可证与归属清单；
- 每包文化审核版本；
- 未引用和重复资产报告；
- 高分辨率源图误入报告；
- PNG/JPEG/KTX/GLB/音频的白名单报告；
- 三档真机截图与性能证据；
- 通用球场离线恢复证据。

没有完整报告的资源包不上传 CDN，也不进入微信提审目录。
