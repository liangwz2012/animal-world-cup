# 动物足球赛：横版排行榜与好友对战设计

日期：2026-07-28

## 目标

在保持横版比赛体验的前提下，为小游戏增加可持续游玩的单人排位闭环、真实玩家排行榜和好友邀请对战。玩家无需在进入游戏时登录；仅在首次主动上榜时建立档案，之后本机静默恢复身份。

## 范围与阶段

### 第一阶段：本次改造

- 横版首页增加“排行榜”和“好友对战”入口；排行榜以右侧抽屉或横版面板展示，不使用竖版页面。
- 首次上榜档案：玩家主动选择头像、确认昵称并同意公开展示；以后可修改或注销。
- 本机统计与全服赛季榜：赛季积分、胜场、胜率、总进球、净胜球、最长连胜、单场最高进球。
- 统一规则的单人“排位赛”与“每日挑战”；普通单机比赛只进入本机统计。
- 好友建房、微信转发邀请、好友加入、房主 AI 热身、正式双人比赛、独立好友战绩。
- 腾讯云排行榜服务、HTTPS API、持久化数据、头像存储和基础反作弊。

### 第二阶段：不阻塞本次发布

- 8 队联赛征程（杯赛）。
- 球队图鉴、称号与成就奖励。
- 好友榜和赛季奖励。
- 陌生人匹配。不在本次范围内。

## 用户体验

### 横版首页

主界面保持 16:9 横屏。顶部显示已上榜玩家的头像、昵称、赛季积分和当前名次；未建档玩家显示“上榜创建档案”。底部或中部提供：

1. 立即开赛：现有单人普通比赛。
2. 赛季排位：统一难度、时长与结算规则，结果计入全服榜。
3. 每日挑战：每日固定对阵和规则，单独展示当日最好成绩。
4. 好友对战：创建或加入邀请房间。
5. 排行榜：右侧抽屉，显示全球榜、本人排名及本机统计。

### 建档与会话

- 游戏启动和普通比赛永不强制登录。
- 首次点击“上榜”或首次完成可提交的排位赛时，显示横版档案卡：头像选择、昵称确认、用途说明、确认上榜。
- 客户端调用 `wx.login` 获取一次性 code；此过程不显示自定义登录页。服务端以 code 交换微信身份，只保存加盐哈希后的内部账号键。
- 服务端返回不透明会话令牌；客户端通过微信本地存储保存令牌、玩家资料和最近榜单缓存。
- 令牌有效时静默恢复；过期时在后台刷新身份。刷新失败不打断游戏，只在用户主动上榜或提交赛果时提示重试。
- 用户可在“我的档案”修改头像昵称、退出排行榜或请求删除档案及全部服务器统计。

### 好友对战

1. 房主在横版首页选球队和阵型，点击“好友对战”。
2. 客户端静默认证后创建 10 分钟有效的两人房间，生成微信分享卡片与邀请参数。
3. 房主转发给好友；等待时可以进行 AI 热身，邀请不失效。
4. 好友通过微信卡片打开小游戏后自动读取邀请并加入房间；可观战房主热身。
5. 房主看到“好友已加入”后点击“开始好友对战”，双方进入同一场正式比赛；红方和蓝方实时同步。
6. 好友战绩单独记录胜负、进球与连胜，不计入全服赛季积分，避免互相刷分。

## 排行榜与积分

### 数据口径

全服赛季榜只接受服务器签发比赛编号的排位赛结果。普通单机赛和好友赛只保存在本机或好友战绩中。

| 榜单 | 数据 | 准入规则 |
| --- | --- | --- |
| 赛季积分 | 初始积分、胜平负结果 | 完成至少 5 场排位后显示具体名次 |
| 胜场 | 排位赛获胜总数 | 无 |
| 胜率 | 胜场/有效排位场次 | 至少 20 场 |
| 进球 | 排位赛总进球 | 无 |
| 净胜球 | 进球减失球 | 无 |
| 最长连胜 | 连续排位胜场 | 无 |
| 单场最高进球 | 单场排位个人进球 | 无 |

### 积分规则

- 初始赛季积分为 1000。
- 胜利加分、失败扣分、平局小幅调整；净胜球奖励设上限，不能通过大比分反复刷分。
- 每日挑战独立排名，不改变赛季积分。
- 每场排位使用服务端签发的比赛编号、开始时间、规则版本和过期时间；同一编号只能结算一次。

### 基础反作弊

- 服务端校验会话、比赛编号、配置、比赛时长、比分边界、每日次数、提交频率与重复结果。
- 异常高频、超出规则的比分或过期赛果拒绝入榜并保留审计记录。
- 本次不提供任何现金或可交易奖励，因此不实现服务器完整物理复算；排行榜标注为游戏赛季数据，后续按作弊情况增强风控。

## 服务端与部署

### 目标结构

```
小游戏客户端
  ├─ HTTPS https://master-ai.cn/animal-rank/v1  排行榜、档案、赛果、头像
  └─ WSS   https://master-ai.cn/animal-ws       好友房间与实时同步

Nginx（TLS、限流、静态头像）
  ├─ animal-rank-api（独立 PM2 进程）
  └─ animal-friend-room（独立 PM2 进程）

持久化数据目录
  ├─ SQLite 数据库
  └─ avatars/ 经过类型、尺寸和大小校验的公开头像
```

`master-ai.cn` 已在历史部署方案中记录为 HTTPS、Nginx、PM2 环境。本次必须先在服务器验证当前应用和反向代理，再新增独立进程与独立 Nginx location；不修改已有站点进程。当前腾讯云实例信息与 `master-ai.cn` 的公开解析地址不一致，部署前须在服务器侧确认最终主机归属，禁止凭 IP 猜测或覆盖现有服务。

### API

所有接口以 `/animal-rank/v1` 为前缀：

- `POST /session/exchange`：微信 code 或已有会话换取不透明会话令牌。
- `GET /me`、`PATCH /me`、`DELETE /me`：读取、更新和删除档案。
- `POST /me/avatar`：上传经过限制的头像。
- `GET /leaderboards/:metric`：读取指定榜单及本人名次。
- `POST /ranked-matches`：领取排位比赛编号。
- `POST /ranked-matches/:id/result`：提交一次性赛果。
- `GET /daily-challenge`：获取当天固定挑战规则和本人成绩。
- `POST /daily-challenge/:id/result`：提交每日挑战赛果。

好友房间继续使用现有 WebSocket 协议；在正式 WSS 地址部署、登记合法域名并完成双真机验收前，不在首页公开启用入口。

## 数据模型

- `players`：内部账号键、会话版本、昵称、头像路径、创建/更新时间、注销时间。
- `season_stats`：玩家、赛季、积分、场次、胜平负、进失球、连胜、峰值、更新时间。
- `ranked_matches`：比赛编号、玩家、规则版本、开始/过期/结算时间、提交状态、赛果摘要。
- `daily_challenges`：日期、对阵、固定规则、挑战版本。
- `daily_results`：玩家、挑战、最佳成绩、提交时间。
- `friend_match_history`：玩家、对手内部键、赛果、时间；不参与全服榜。
- `audit_events`：拒绝赛果、异常频率、删除请求等安全审计。

## 隐私与合规

隐私指引必须由“未处理任何信息”改为如实声明：

- 头像：玩家主动选择，用于排行榜和好友战绩展示。
- 昵称：玩家主动填写，用于排行榜和好友战绩展示。
- 内部账号标识：微信登录后生成，用于身份恢复、反冒用和删除请求；不对外展示。
- 比赛成绩及统计：用于计算赛季排名、每日挑战和本机/好友战绩。

不收集手机号、通讯录、地理位置或相册写入权限。头像上传前需明示用途；档案注销时删除头像、会话与统计数据。生产请求域名 `https://master-ai.cn` 必须在微信公众平台登记为 request 合法域名，好友功能启用时还需登记对应 socket 合法域名。

## 验收

### 自动化

- 档案会话恢复、令牌失效降级、积分计算、榜单排序、阈值准入、重复赛果拒绝和删除流程均有单元测试。
- API 的身份、限流、边界比分和头像上传校验有集成测试。
- 现有好友房协议测试继续通过。

### 真机与上线

- 冷启动、热启动、切后台后不出现资料页或重复登录。
- 首次上榜能创建并展示头像昵称；修改与注销立即生效。
- 排位赛和每日挑战正确写入对应榜单；普通赛不上传。
- 两台真机完成建房、转发、冷/热启动加入、AI 热身、好友正式局、断线恢复与赛果一致性验收。
- 微信公众平台配置 request/socket 合法域名，并更新隐私指引后再提交含联网功能的版本。
