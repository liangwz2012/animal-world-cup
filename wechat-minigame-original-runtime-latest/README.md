# 微信小游戏原版 Runtime 静态移植（最新版）

这是一个独立验证项目，只移植现有网页比赛引擎，不重写玩法、物理、AI、球队资源或画面风格。

## 当前实测状态（2026-07-11）

- 微信开发者工具 Stable 2.01.2510290 已出现原版可见比赛画面。
- 控制台已达到 `B2_VISIBLE_MATCH_STARTED`，运行的是 Pixi 4.8.9 WebGL 和原版比赛模块，无简化比赛回退。
- 已复用原网站手机控制方案并改为 Pixi Canvas 覆盖层：左摇杆、挑传、传球、铲球、射门和中央冲刺均已在开发者工具中显示。
- 控制层从原版 AMD `pixi` 模块取得同一套 `Container/Graphics` 构造器，冷编译后控制台为 0 个错误。
- 双指移动+动作、单次动作脉冲、射门/冲刺长按及松手清零已通过自动测试；真手指操控仍待真机确认。
- 修复触控诊断镜像在 `GameGlobal === globalThis` 时的 getter 自递归；重新执行“编译”后仍能进入比赛，控制台为 0 个错误。
- 冷编译后的持续观察中比赛镜头、AI、球员和足球正常更新；旧 Pixi 的弃用提示仍作为警告保留，不影响本次启动结论。
- 原版闭包读取的 `window.__touchInput` 已通过同引用硬闸门，确认绑定微信共享触控对象。
- 移动 `vx/vy`、冲刺、传球、射门、切人映射已有自动测试。
- 桌面模拟器不会把鼠标拖动转换为 `wx.onTouch*`；真机触摸手感、帧率、内存和长局稳定性仍需真机调试，当前不宣称已可提审。
- 当前静态体积约为：主包 1.37 MiB，普通资源分包 9.77 MiB，总计约 11.14 MiB；未降低原版贴图质量。当前微信小游戏规则下，普通分包不受独立分包的 4 MiB 单包限制，主包低于 4 MiB且总量低于 20 MiB，静态包体闸门已通过。
- 构建改为暂存目录完成后再原子替换产物；静态替换失败时不会再清空上一份可预览版本，也不会留下缺少 `runtime-assets/game.js` 的残缺分包。
- 已根治 `indicators/sight.png does not exist in the texture cache` 的随机启动弹窗：关键图集在开赛前硬预载并校验，场景创建前再次恢复缓存；同类缓存异常会静默自恢复，不再显示阻塞式“原版引擎移植失败”弹窗。
- 真机不再执行原网页的高内存动态观众图集烘焙；iOS/Android 直接使用球场静态观众背景加载核心比赛资源，解决手机长期卡在 82%。开发者工具保留动态观众，并设有 12 秒超时降级。核心加载进度现映射到 82%-98%，不再假性停住。
- 首页底部为对称入口：左“观看对战”、中间金色“立即开赛”、右“好友对战”；球队、双方阵型、难度和时长均完整保留。提审版经 `FRIEND_ENTRY_ENABLED=false`（`src/net/friend-service-config.js`）临时隐藏好友入口并退为两键布局，正式 WSS 部署并登记 Socket 合法域名后改回 `true` 即恢复。
- 好友入口已经串通建房、微信转发、等待时 AI 热身、好友上线提示、热身观战、踢完自动开好友局和正式蓝方操控。
- 联机采用房主 60 Hz 权威模拟、20 Hz 二进制比赛帧、好友 120 ms 插值和 30 Hz 蓝方输入；好友端禁止本地物理，不存在双方各跑一局的假同步回退。
- `touchInput2` 在生成脚本加载前后都会按实际 runtime window 重绑；单机不再因好友蓝方通道的热重载标记出现 B1 FATAL，好友局则保留开赛前硬校验。

## 与旧尝试的关键区别

- 所有原版脚本在构建期转成静态模块，运行期没有 `eval` / `new Function`。
- 修复旧 shim 忽略 AMD 依赖数组的问题。
- Pixi 4.8.9 直接使用微信原生 WebGL，不再用 Canvas2D 假装 WebGL。
- 原版 renderer 通过 `rendererOptions.view` 显式绑定唯一主 Canvas。
- 任一分包、模块或启动错误都会硬失败并显示诊断，不存在简化版回退。

## 构建和检查

```bash
cd wechat-minigame-original-runtime-latest
npm run check
```

开发者工具本机联调好友房时，另开终端运行：

```bash
npm run server:dev
```

本机服务固定使用 `ws://127.0.0.1:18787` 且必须显式开启 `DEV_AUTH`，只供开发者工具使用。真机和正式发布必须在 `src/net/friend-service-config.js` 填写已部署的 `wss://` 地址，并在微信公众平台登记 Socket 合法域名；服务端的 AppSecret 只能放在服务端环境变量中。

准备上传提审前必须另外执行：

```bash
npm run release:check
```

`release:check` 会在著作权人、出版服务单位、批准文号、出版物号、软件著作权登记号、小程序备案号或正式 WSS 房间服务缺失时阻止提审。真实资质统一填写在 `src/data/release-compliance.js`，必须与微信公众平台登记内容逐字一致，禁止使用占位或编造信息。好友对战完成双真机整局验收前不得上传提审。

正式 AppID 已由微信小游戏健康系统自动展示防沉迷与《健康游戏忠告》页面，因此游戏内不再重复增加第二层忠告页；平台页结束后直接进入品牌加载与选队页面。

然后用微信开发者工具打开本目录。验收标记在全局变量：

- `__ORIGINAL_RUNTIME_LATEST_STAGE__ === "B1_MODULES_REGISTERED"`：原版模块已正确注册。
- `__ORIGINAL_RUNTIME_LATEST_STAGE__ === "B2_VISIBLE_MATCH_STARTED"`：原版资源加载完成并进入比赛。
- `__ORIGINAL_RUNTIME_ACTIVE__ === true`：当前运行的是原版比赛 runtime，不是替代实现。
- `__ORIGINAL_RUNTIME_TOUCH_BINDING_OK__ === true`：原版控制器读取的是微信共享触控对象。
- `__ORIGINAL_RUNTIME_CONTROLS_VISIBLE__ === true`：原网站触控层已经挂到原版 Pixi 舞台。
- `__ORIGINAL_RUNTIME_TOUCH2_BINDING_OK__ === true`：第二玩家输入已绑定到实际原版 runtime window；单机模式即使该诊断降级也不会弹致命错误。
- `__ANIMAL_FOOTBALL_APP__.friend`：当前好友房角色、房间状态、排队和联机阶段诊断。

静态检查通过只说明构建链成立；只有开发者工具或真机出现原版可见比赛首帧，才算 B2 通过。
